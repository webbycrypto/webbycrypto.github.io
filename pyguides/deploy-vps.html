VPS Setup + SSH

Get a Linux server, log in with SSH, harden it, install Python, upload your app, and run uvicorn. By the end of this guide your FastAPI app is accessible on the internet — albeit without HTTPS or a proper process manager yet.

1

What is a VPS?

A VPS (Virtual Private Server) is a Linux computer you rent in a data centre. It runs 24/7, has a public IP address, and is accessible from anywhere. You connect to it with SSH — like a terminal but over the internet. Your FastAPI app runs on it as a process.

How to pick: For a hobby project or early SaaS, a $5–6/month server (2GB RAM, 1 vCPU) is plenty. Hetzner CAX11 (~€4.15/mo) is the best value in Europe. DigitalOcean Droplet ($6/mo) has the best docs for beginners. Both use Ubuntu 22.04 LTS — the most widely documented Linux for hosting.
2

Creating the Server

Before clicking "Create", generate an SSH key on your local machine. This is the credential you'll use to log in — more secure than a password and required by most providers.

bash — run on your local machine
# Generate a new SSH key pair
ssh-keygen -t ed25519 -C "your-email@example.com"
# Press Enter to accept the default path (~/.ssh/id_ed25519)
# Set a passphrase (recommended) or leave blank

# View the PUBLIC key — this is what you paste into the provider's UI
cat ~/.ssh/id_ed25519.pub
# → ssh-ed25519 AAAAC3Nz... your-email@example.com

# Windows: run this in PowerShell or Git Bash
# The key files are in C:\Users\you\.ssh\
text — server creation steps
DigitalOcean:
  1. Create account at digitalocean.com
  2. New Droplet → Ubuntu 22.04 LTS → Basic → Regular → $6/mo
  3. Authentication: SSH Key → paste your id_ed25519.pub contents
  4. Choose a datacenter close to your users
  5. Create Droplet → copy the IP address

Hetzner:
  1. Create account at hetzner.com/cloud
  2. New Server → Ubuntu 22.04 → CX11 (cheapest) or CAX11 (ARM, cheaper)
  3. SSH keys → Add SSH key → paste id_ed25519.pub
  4. Create → copy the IP address

Both give you a server with root access via SSH in ~60 seconds.

First Login — Create a Non-Root User

Your first login is as root. Immediately create a regular user with sudo access — running apps as root is a security risk. After creating the user, log in as them for everything else.

bash
# Log in as root (replace with your server's IP)
ssh root@YOUR_SERVER_IP

# Create a new user (replace "deploy" with any username you like)
adduser deploy
# Enter a password and fill in the prompts (or press Enter to skip)

# Give the new user sudo access
usermod -aG sudo deploy

# Copy your SSH key to the new user so you can log in as them
rsync --archive --chown=deploy:deploy ~/.ssh /home/deploy

# Log out of root
exit

# Log back in as your new user
ssh deploy@YOUR_SERVER_IP
# You should be logged in without a password (SSH key auth)

Firewall + Basic Hardening

Enable the firewall, allow only the ports you need, and disable root login via SSH. These three steps stop the majority of automated attacks that scan the internet for open servers.

bash
# ── Firewall (ufw = Uncomplicated Firewall) ──────────────────
sudo ufw allow OpenSSH   # allow SSH (port 22) — DO THIS FIRST or you'll lock yourself out
sudo ufw allow 80        # HTTP
sudo ufw allow 443       # HTTPS
sudo ufw enable          # turn the firewall on
sudo ufw status          # verify — should show 22, 80, 443 allowed

# ── Disable root SSH login ───────────────────────────────────
sudo nano /etc/ssh/sshd_config
# Find:  PermitRootLogin yes
# Change to:  PermitRootLogin no
# Save with Ctrl+O, exit with Ctrl+X

sudo systemctl restart ssh   # apply the SSH config change

# ── Update packages ──────────────────────────────────────────
sudo apt update && sudo apt upgrade -y
Always allow SSH before enabling ufw. If you run ufw enable without first allowing port 22, you will lock yourself out of the server and need to use the provider's web console to fix it.
5

Install Python

Ubuntu 22.04 comes with Python 3.10. Install pip and venv so you can create a virtual environment for your app.

bash
sudo apt install -y python3-pip python3-venv python3-dev

# Verify
python3 --version   # Python 3.10.x or newer
pip3 --version
Why venv? A virtual environment isolates your app's dependencies from the system Python. If you install packages globally, different apps on the same server can conflict. venv gives each app its own isolated set of packages.

Upload Your App

The recommended way is to push your code to GitHub and clone it on the server. Alternatively, use scp to copy files directly.

bash — on the server
# Choose a directory for your apps
mkdir -p /home/deploy/apps
cd /home/deploy/apps

# Clone your repo (use HTTPS for read-only access)
git clone https://github.com/yourusername/yourapp.git
cd yourapp

# Future deploys: just git pull
git pull origin main
bash — run on your LOCAL machine
# Copy your project folder to the server
scp -r ./myapp deploy@YOUR_SERVER_IP:/home/deploy/apps/

# Or copy a single file:
scp main.py deploy@YOUR_SERVER_IP:/home/deploy/apps/myapp/
7

Create venv + Install Dependencies

bash
cd /home/deploy/apps/yourapp

# Create a virtual environment named "venv" inside the project folder
python3 -m venv venv

# Activate it
source venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Verify FastAPI and uvicorn are installed
python -c "import fastapi, uvicorn; print('OK')"

# The venv stays active only for this terminal session
# systemd will activate it automatically (covered in deploy-systemd.html)
8

Run uvicorn Manually

Test that the app starts. Bind to 0.0.0.0 so it listens on all network interfaces (not just localhost), and port 8000.

bash
source venv/bin/activate

# Start uvicorn bound to all interfaces
uvicorn main:app --host 0.0.0.0 --port 8000

# Visit in your browser: http://YOUR_SERVER_IP:8000
# Or: http://YOUR_SERVER_IP:8000/docs

# Stop with Ctrl+C
If you see a "Connection refused" error in the browser, check that port 8000 isn't blocked by ufw: sudo ufw allow 8000. Then remove it again after testing: sudo ufw delete allow 8000. In production, Nginx handles port 80/443 and proxies to uvicorn on 8000 internally.

What's Wrong With Running It Manually

The manual uvicorn run works for testing but isn't suitable for production. Three problems need to be fixed in the next guides.

text
PROBLEM 1: Dies when you close the terminal
  When you SSH out, the process stops.
  Fix: systemd service (deploy-systemd.html)

PROBLEM 2: Port 8000 is exposed directly
  Users would type http://yoursite.com:8000 — ugly and non-standard.
  Port 8000 isn't protected by TLS.
  Fix: Nginx reverse proxy on port 80/443 (deploy-nginx.html)

PROBLEM 3: No HTTPS
  Browsers warn about insecure connections.
  Passwords, tokens, cookies are sent in plaintext.
  Auth cookies require Secure flag → need HTTPS.
  Fix: Certbot (deploy-ssl.html)
