Todo App - Django

Build a todo app the Django way - model, views, URL routing, and templates. Focus is entirely on the frontend and database, using Django's built-in ORM, form handling, and admin panel.

1

Before You Start

A few concepts will make Django's structure much easier to understand before you run your first command. Virtual environments keep your project's packages isolated from the rest of your system - activate one before installing anything, and you will see (venv) in your prompt each time it is active. HTTP is the protocol browsers use to communicate with servers: a GET request loads a page, and a POST request sends form data to be processed. Django views check request.method to tell these apart - 'POST' means the user submitted a form, anything else means they just loaded the page. A database stores your app's data in an organised way; Django uses SQLite by default, which is a plain file (db.sqlite3) requiring zero configuration. Django's ORM (Object Relational Mapper) lets you work with that database using Python classes - you define a model and Django writes the SQL for you, so you never need to write CREATE TABLE or INSERT statements manually.

bash 
# Create a virtual environment in your project folder
python -m venv venv

# Activate it - run this every time you open a new terminal
venv\Scripts\activate        # Windows
source venv/bin/activate      # macOS / Linux

# Your prompt will show (venv) when it is active.
# Install Django:
pip install django

# Or install offline if you have already downloaded the bundle:
pyoffline install --bundle django

# Verify the install:
python -m django --version

Project Setup

Django makes a distinction between a project (the whole website - settings, URL routing, configuration) and an app (a self-contained feature module inside the project, like a todo list). One project can contain many apps, and apps can be reused across projects. manage.py is a command-line tool Django generates for you - almost every Django operation goes through it: running the server, creating migrations, creating admin users, and more. The dot at the end of django-admin startproject todoproject . tells Django to use the current folder as the project root instead of creating a new subfolder - this keeps the folder structure flat and easier to work with. Registering your app in INSTALLED_APPS tells Django it exists, so the ORM can find its models when building migrations and the template loader can find its templates.

bash 
# Create the project and app
django-admin startproject todoproject .    # the dot uses the current folder
python manage.py startapp todos            # creates the todos/ app folder

# After writing your model, create and apply the migration
python manage.py makemigrations
python manage.py migrate

# Create an admin user to access /admin
python manage.py createsuperuser

# Run the development server
python manage.py runserver
python 
INSTALLED_APPS = [
    # ... existing Django apps ...
    'todos',   # register the todos app
]

# Tell Django where to look for a shared templates/ folder
TEMPLATES = [{
    ...
    'DIRS': [BASE_DIR / 'templates'],
    ...
}]

Todo Model

A Django model is a Python class where each attribute maps to a column in a database table. Django's ORM translates these class definitions into SQL CREATE TABLE statements so you never write raw SQL just to set up your schema. After writing or changing a model, you must run two commands: makemigrations generates a migration file (a Python script describing the database change), and migrate applies that script to the actual database. auto_now_add=True sets the timestamp once when the record is first created and never changes it again - this is different from auto_now=True, which updates the timestamp every time the record is saved. Meta.ordering = ['done', '-created_at'] tells Django to sort query results by default - incomplete todos first (False sorts before True), then newest within each group. The __str__ method controls how a Todo object appears in the Django admin panel and in the Python shell.

python 
from django.db import models

class Todo(models.Model):
    title      = models.CharField(max_length=200)
    done       = models.BooleanField(default=False)
    created_at = models.DateTimeField(auto_now_add=True)  # set once when created

    class Meta:
        ordering = ['done', '-created_at']  # incomplete first, then newest

    def __str__(self):
        status = "✓" if self.done else "○"
        return f"{status} {self.title}"

# Register in todos/admin.py so todos appear in the admin panel
# (see Step 7)

Views - List, Create, Toggle, Delete

A Django view is a Python function that receives an HttpRequest object and must return an HttpResponse - that is the complete contract. The list view queries all todos and passes them to the template as a dictionary (called the context); the template then loops over them. The create, toggle, and delete views always redirect after making a change - this is the Post/Redirect/Get pattern. Without it, pressing browser refresh would re-submit the last POST and create a duplicate task or repeat the delete. get_object_or_404(Todo, pk=pk) is a shortcut that does a .get() lookup and automatically returns a 404 page if the object is not found - without it you would need to catch the Todo.DoesNotExist exception manually. messages.success() and messages.error() store feedback messages in the session; they survive the redirect and are displayed by the base template on the next page load.

python 
from django.shortcuts import render, get_object_or_404, redirect
from django.contrib import messages
from .models import Todo

def todo_list(request):
    todos = Todo.objects.all()  # the model's Meta.ordering applies automatically
    return render(request, "todos/list.html", {"todos": todos})

def todo_create(request):
    if request.method == "POST":
        title = request.POST.get("title", "").strip()
        if title:
            Todo.objects.create(title=title)
            messages.success(request, "Task added!")
        else:
            messages.error(request, "Please enter a task.")
    return redirect("todo_list")  # always redirect after POST

def todo_toggle(request, pk):
    todo = get_object_or_404(Todo, pk=pk)
    todo.done = not todo.done   # flip the done flag
    todo.save()
    return redirect("todo_list")

def todo_delete(request, pk):
    todo = get_object_or_404(Todo, pk=pk)
    todo.delete()
    messages.info(request, "Task deleted.")
    return redirect("todo_list")

URL Configuration

Django's URL routing works by matching the incoming request path against a list of patterns defined in urlpatterns. Each pattern maps a path to a view function. Every app has its own urls.py file containing only its own routes - the project's main urls.py then pulls them all in with include(). This keeps each app self-contained: if you want to reuse the todos app in a different project, you bring its urls.py with it. The name= argument on each path is important: it lets you generate the correct URL in templates using {% url 'todo_list' %} and in Python using reverse('todo_list') - if you ever change the URL path, links using the name still work without editing every template. The <int:pk> part in path patterns is a URL converter - it captures that segment of the URL and passes it to the view as an integer called pk.

python 
from django.urls import path
from . import views

urlpatterns = [
    path("",                views.todo_list,   name="todo_list"),
    path("add/",            views.todo_create, name="todo_create"),
    path("toggle/<int:pk>/",views.todo_toggle, name="todo_toggle"),
    path("delete/<int:pk>/",views.todo_delete, name="todo_delete"),
]
python 
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path("admin/", admin.site.urls),
    path("",       include("todos.urls")),  # mount the todos app at the root URL
]

Base Template

The base template is the shared page shell - header, global CSS, and message display - that all other templates inherit from. Child templates use {% extends 'base.html' %} to opt in to this inheritance, then define {% block %} sections to replace specific parts. Everything outside a block is fixed: the header and styles are always there. Django's message framework works like Flask's flash messages - a view calls messages.success() or messages.error(), the message is stored in the session, and the base template displays it once on the next page load before clearing it. The {{ message.tags }} expression outputs the message's tag string as a CSS class name - Django maps 'success' to 'success', 'error' to 'error', and so on, which matches the CSS classes defined in the style block so each type gets a different background colour.

html 
<!DOCTYPE html>
<class="hl-tag">html lang="en">
<class="hl-tag">head>
  <class="hl-tag">meta charset="UTF-8">
  <class="hl-tag">meta name="viewport" content="width=device-width, initial-scale=1">
  <class="hl-tag">title>{% block title %}Django Todo{% endblock %}</class="hl-tag">title>
  <class="hl-tag">style>
    * { box-sizing: border-box; margin: 0; padding: 0; }
    body { font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
           background: #f5f7fa; color: #1a1a1a; }
    header { background: #092e20; color: white; padding: 14px 24px;
             font-size: 1.1rem; font-weight: 600; }
    .container { max-width: 600px; margin: 40px auto; padding: 0 20px; }
    .msg { padding: 10px 16px; border-radius: 6px; margin-bottom: 12px; font-size: .9rem; }
    .msg.success { background: #d4edda; color: #155724; }

Todo List Template

This template extends base.html and fills in two blocks: the page title and the main content. The {% for todo in todos %} loop iterates over the list of Todo objects passed in by the view - Django templates use {{ }} to output a value and {% %} for logic like loops and conditionals. The {% csrf_token %} tag inside the form is required by Django's CSRF protection - it injects a hidden input with a unique token that Django checks when the form is submitted; without it, Django returns a 403 Forbidden error. {% url 'todo_create' %} generates the correct URL for the todo_create view by name - much safer than typing /add/ by hand, since renaming the route in urls.py automatically updates every reference. {{ todo.created_at|date:'N j' }} applies Django's built-in date filter to format the timestamp - 'N j' means abbreviated month name and day number (e.g. 'May 26'). Toggle and delete are plain links that fire GET requests - no JavaScript needed at all.

html 
{% extends "base.html" %}
{% block title %}My Tasks{% endblock %}

{% block extra_styles %}

                    border-radius: 6px; font-size: 1rem; }

                     border: none; border-radius: 6px; cursor: pointer; }

{% endblock %}

Django Admin Panel

Django ships with a complete admin panel at /admin - a full CRUD interface for your data that you get for free without writing any views, templates, or forms. To make a model appear there, you register it in the app's admin.py file. Using the @admin.register(Todo) decorator is equivalent to the older admin.site.register(Todo, TodoAdmin) syntax - just cleaner. The list_display list controls which columns appear in the list view; list_filter adds a sidebar with clickable filter buttons; search_fields adds a search box that queries those fields. The actions list defines bulk operations - the user selects multiple rows and applies an action to all of them at once. To access the admin panel, create a superuser first with python manage.py createsuperuser, then visit http://localhost:8000/admin and log in.

python 
from django.contrib import admin
from .models import Todo

@admin.register(Todo)
class TodoAdmin(admin.ModelAdmin):
    list_display  = ["title", "done", "created_at"]   # columns shown in the list view
    list_filter   = ["done"]                           # sidebar filter by done/not done
    search_fields = ["title"]                          # search box filters by title
    ordering      = ["done", "-created_at"]            # same order as the main view
    actions       = ["mark_done", "mark_undone"]

    @admin.action(description="Mark selected tasks as done")
    def mark_done(self, request, queryset):
        queryset.update(done=True)

    @admin.action(description="Mark selected tasks as not done")
    def mark_undone(self, request, queryset):
        queryset.update(done=False)

# Visit http://localhost:8000/admin after creating a superuser with:
# python manage.py createsuperuser
