WebSockets with FastAPI

Build real-time features — live chat, dashboards, notifications, and multiplayer games — using FastAPI's native WebSocket support. No polling required.

1

What are WebSockets?

The normal HTTP request cycle is one-directional and short-lived: the browser sends a request, the server sends one response, and the connection closes. If you want to check for new messages, you have to send another request — this is called polling, and it is wasteful. A WebSocket is a persistent, two-way connection. The browser and server do a one-time "handshake" over HTTP and then upgrade to a WebSocket connection that stays open. After that, either side can send data to the other at any time without a new request — the server can push a message to the browser the moment something happens. This is what makes live chat, real-time dashboards, collaborative editors, and live notifications possible without polling every few seconds.

Use WebSockets when: you need the server to push data to the client without the client asking — live notifications, chat messages, price tickers, progress updates. Use regular HTTP (polling or Server-Sent Events) when updates are infrequent or one-directional.

Your First WebSocket Route

FastAPI adds WebSocket support with almost no extra setup. Instead of @app.get or @app.post, you use @app.websocket. The route function receives a WebSocket object instead of a Request. The first thing you always do inside the function is call await websocket.accept() — this completes the handshake and upgrades the connection from HTTP to WebSocket. Without this call, the browser's connection will immediately fail. Then you enter a loop — while True — because the connection is persistent. Inside the loop, await websocket.receive_text() waits until the client sends a message, and await websocket.send_text() pushes a message back to the client. The async keyword and await are required because WebSocket communication is I/O-bound and FastAPI is built on asyncio.

python
from fastapi import FastAPI, WebSocket

app = FastAPI()


# @app.websocket — same as @app.get but for WebSocket connections
@app.websocket("/ws")
async def websocket_endpoint(websocket: WebSocket):
    # Step 1: accept the connection — completes the HTTP → WebSocket upgrade
    # Without this the browser gets a connection refused error
    await websocket.accept()

    # Step 2: loop forever — the connection stays open until it's closed
    while True:
        # Wait for the next message from the client (blocks until one arrives)
        data = await websocket.receive_text()

        # Echo it back with a prefix — simple echo server
        await websocket.send_text(f"You said: {data}")
javascript
// Open the browser DevTools (F12) → Console tab
// Paste this to test your WebSocket server

// Create a WebSocket connection to the server
const ws = new WebSocket("ws://localhost:8000/ws");

// Fires when the connection is established
ws.onopen = () => console.log("Connected!");

// Fires every time the server sends a message
ws.onmessage = (event) => console.log("Server:", event.data);

// Send a message to the server
ws.send("Hello from the browser");

// Expected in console:
// Connected!
// Server: You said: Hello from the browser

Sending JSON Messages

receive_text() and send_text() work fine for plain strings, but real apps exchange structured data — a message with a username, timestamp, and content, for example. WebSocket has receive_json() and send_json() methods that handle the JSON serialisation and deserialisation for you. You can also mix text and JSON in the same connection. On the JavaScript side, JSON.parse() and JSON.stringify() are the counterparts. A good convention is to always send JSON objects with a type field — this lets you handle different kinds of messages in the same connection, similar to how Redux actions work. For example, a chat app might send {type: "message", content: "..."} and {type: "typing", user: "alice"} through the same WebSocket.

python
from datetime import datetime

@app.websocket("/ws")
async def websocket_endpoint(websocket: WebSocket):
    await websocket.accept()

    while True:
        # receive_json() parses the incoming JSON automatically
        # Returns a dict — no need to call json.loads() yourself
        data = await websocket.receive_json()

        # data is now a Python dict — access fields normally
        username = data.get("username", "Anonymous")
        content  = data.get("content", "")

        # send_json() serialises a dict to JSON automatically
        await websocket.send_json({
            "type":      "message",
            "username":  username,
            "content":   content,
            "timestamp": datetime.utcnow().isoformat()
        })
javascript
const ws = new WebSocket("ws://localhost:8000/ws");

ws.onopen = () => {
  // JSON.stringify() serialises the object to a JSON string before sending
  ws.send(JSON.stringify({
    username: "alice",
    content:  "Hello everyone!"
  }));
};

ws.onmessage = (event) => {
  // JSON.parse() deserialises the server's JSON string back to an object
  const msg = JSON.parse(event.data);

  // Use the type field to handle different kinds of messages
  if (msg.type === "message") {
    console.log(`[${msg.timestamp}] ${msg.username}: ${msg.content}`);
  } else if (msg.type === "typing") {
    console.log(`${msg.username} is typing...`);
  }
};

The Connection Manager

A single-user echo server is fine for learning, but real apps have many clients connected at once. The standard pattern in FastAPI WebSocket apps is a ConnectionManager class that keeps a list of active connections and provides connect(), disconnect(), and send methods. The list is a module-level singleton — it lives for the lifetime of the server process, shared across all requests. When a new client connects, you add their WebSocket to the list. When they disconnect, you remove it. This class becomes the central hub through which all messages are routed. If you are running multiple server processes (like with gunicorn workers), each process has its own list — they do not share state. In that case you need Redis pub/sub to coordinate across processes, but a single process handles thousands of concurrent WebSocket connections fine.

python
from fastapi import WebSocket
from typing import List


class ConnectionManager:
    def __init__(self):
        # List of all currently connected WebSocket objects
        self.active_connections: List[WebSocket] = []

    async def connect(self, websocket: WebSocket):
        await websocket.accept()                       # complete the handshake
        self.active_connections.append(websocket)   # add to the list

    def disconnect(self, websocket: WebSocket):
        self.active_connections.remove(websocket)   # remove when they leave

    async def send_personal(self, message: str, websocket: WebSocket):
        # Send to one specific client
        await websocket.send_text(message)

    async def broadcast(self, message: str):
        # Send to every connected client
        for connection in self.active_connections:
            await connection.send_text(message)


# Module-level singleton — shared across all WebSocket route calls
manager = ConnectionManager()
python
from fastapi import WebSocketDisconnect

@app.websocket("/ws/{client_id}")
async def websocket_endpoint(websocket: WebSocket, client_id: int):
    # connect() accepts the handshake AND adds this socket to the list
    await manager.connect(websocket)

    try:
        while True:
            data = await websocket.receive_text()
            # Send the message back to this user privately
            await manager.send_personal(f"You: {data}", websocket)
            # Send to everyone else
            await manager.broadcast(f"Client #{client_id}: {data}")

    except WebSocketDisconnect:
        # WebSocketDisconnect is raised when the client closes the tab or loses connection
        manager.disconnect(websocket)
        await manager.broadcast(f"Client #{client_id} left the chat")

Broadcasting to All Clients

Broadcasting sends a message to every connected client simultaneously. It is the core of chat apps, live dashboards, and multiplayer games. The implementation is a simple loop over all connections, but there is an important subtlety: if one client's send_text() raises an exception — because their connection dropped between the time you built the list and the time you sent to them — you need to handle that gracefully or the entire broadcast stops halfway through. The safe pattern wraps each individual send in a try/except and removes failed connections from the list. You should also send JSON with a type field when broadcasting so the client can distinguish between different kinds of updates on the same connection.

python
import json

class ConnectionManager:
    def __init__(self):
        self.active_connections: List[WebSocket] = []

    async def connect(self, websocket: WebSocket):
        await websocket.accept()
        self.active_connections.append(websocket)

    def disconnect(self, websocket: WebSocket):
        if websocket in self.active_connections:
            self.active_connections.remove(websocket)

    async def broadcast_json(self, data: dict):
        # Iterate over a copy of the list — we might modify it mid-loop
        dead = []
        for connection in self.active_connections[:]:
            try:
                await connection.send_json(data)
            except Exception:
                # Connection died — mark it for removal
                dead.append(connection)
        for conn in dead:
            self.disconnect(conn)
python
# A normal REST route that broadcasts to all WebSocket clients
# Useful for server-initiated pushes — e.g. "a new order came in"
@app.post("/admin/announce")
async def announce(message: str):
    await manager.broadcast_json({
        "type":    "announcement",
        "message": message
    })
    return {"sent_to": len(manager.active_connections)}


# Example: broadcast a live price update every second from a background task
import asyncio

@app.on_event("startup")
async def start_price_feed():
    async def feed():
        price = 100.0
        while True:
            price += 0.01
            await manager.broadcast_json({"type": "price", "value": price})
            await asyncio.sleep(1)  # push every second
    asyncio.create_task(feed())  # run feed() in the background forever

Rooms and Named Channels

A chat app with only one global room is rarely useful. Rooms — also called channels or groups — let you broadcast to a subset of connected clients. The implementation uses a dictionary instead of a list: the keys are room names (strings), and the values are lists of WebSocket connections in that room. When a client connects to /ws/chat/python they join the "python" room. When they send a message it only goes to other clients in "python", not to clients in "javascript" or "general". This same pattern applies to any grouping — game lobbies, document collaboration sessions, per-user notification channels. The room name can come from the URL path parameter, a query string, or a message the client sends after connecting.

python
from collections import defaultdict

class RoomManager:
    def __init__(self):
        # defaultdict(list) creates an empty list automatically for new keys
        # rooms["python"] → [ws1, ws2, ...]
        self.rooms: dict[str, List[WebSocket]] = defaultdict(list)

    async def join(self, room: str, websocket: WebSocket):
        await websocket.accept()
        self.rooms[room].append(websocket)

    def leave(self, room: str, websocket: WebSocket):
        if websocket in self.rooms[room]:
            self.rooms[room].remove(websocket)
        # Clean up empty rooms to avoid memory leaks
        if not self.rooms[room]:
            del self.rooms[room]

    async def broadcast_to_room(self, room: str, data: dict):
        for connection in self.rooms.get(room, [])[:]:
            try:
                await connection.send_json(data)
            except Exception:
                self.leave(room, connection)

room_manager = RoomManager()
python
@app.websocket("/ws/chat/{room}")
async def chat_room(websocket: WebSocket, room: str):
    # room comes from the URL: /ws/chat/python → room = "python"
    await room_manager.join(room, websocket)
    await room_manager.broadcast_to_room(room, {
        "type": "system",
        "message": "A new user joined"
    })

    try:
        while True:
            data = await websocket.receive_json()
            # Only broadcast to clients in this same room
            await room_manager.broadcast_to_room(room, {
                "type":    "message",
                "room":    room,
                "content": data.get("content")
            })
    except WebSocketDisconnect:
        room_manager.leave(room, websocket)

Handling Disconnects Cleanly

Clients disconnect for many reasons — they close the browser tab, their internet drops, their phone goes to sleep, or the server restarts. FastAPI raises a WebSocketDisconnect exception when this happens, which is why every WebSocket route should have a try/except block. Without it, an uncaught WebSocketDisconnect crashes the route handler and you never clean up the connection from your manager's list — it stays there as a dead entry, and the next broadcast attempt to it will raise another exception. There is also the question of the server actively closing the connection: websocket.close() sends a proper close frame and terminates the connection from the server side, which you might do after an authentication failure or inactivity timeout.

python
from fastapi import WebSocketDisconnect

@app.websocket("/ws/{client_id}")
async def websocket_endpoint(websocket: WebSocket, client_id: str):
    await manager.connect(websocket)

    try:
        while True:
            data = await websocket.receive_text()
            await manager.broadcast(f"{client_id}: {data}")

    except WebSocketDisconnect:
        # Client disconnected — remove from the list
        manager.disconnect(websocket)
        # Notify everyone else that this user left
        await manager.broadcast(f"{client_id} disconnected")

    except Exception as e:
        # Any other error — still clean up
        manager.disconnect(websocket)
        print(f"Error for {client_id}: {e}")
python
@app.websocket("/ws")
async def secure_ws(websocket: WebSocket, token: str = None):
    # WebSocket connections pass auth via query string: /ws?token=abc
    # (Authorization headers are not accessible in the WebSocket handshake)
    await websocket.accept()  # must accept before you can close with a code

    if not token or not verify_token(token):
        # Close with code 1008 = "policy violation" (auth failure)
        # Codes: 1000=normal, 1001=going away, 1008=policy violation
        await websocket.close(code=1008)
        return

    await manager.connect(websocket)
    try:
        while True:
            data = await websocket.receive_text()
            await manager.broadcast(data)
    except WebSocketDisconnect:
        manager.disconnect(websocket)

HTML Chat Frontend

A working chat app only needs a few dozen lines of HTML and vanilla JavaScript — no framework required. The browser's built-in WebSocket API handles the connection. The key pieces are: the WebSocket constructor which opens the connection, the onmessage handler which fires whenever the server sends something, the onclose handler which detects a dropped connection so you can show a reconnect message, and ws.send() to push messages from the browser to the server. The input field listens for the Enter key so the user does not need to click a button. The messages list is just a div that gets new paragraphs prepended — no state management library needed for something this simple.

html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>WebSocket Chat</title>
  <style>
    body { font-family: sans-serif; max-width: 600px; margin: 40px auto; padding: 0 20px; }
    #messages { border: 1px solid #ccc; height: 300px; overflow-y: auto; padding: 10px; margin-bottom: 10px; }
    #input-row { display: flex; gap: 8px; }
    #messageInput { flex: 1; padding: 8px; }
    #status { font-size: 0.85rem; color: #888; margin-bottom: 8px; }
  </style>
</head>
<body>
  <h2>Live Chat</h2>
  <p id="status">Connecting...</p>
  <div id="messages"></div>
  <div id="input-row">
    <input id="messageInput" placeholder="Type a message..." />
    <button onclick="sendMessage()">Send</button>
  </div>

<script>
  // Generate a random client ID so the server can identify this user
  const clientId = Math.floor(Math.random() * 1000);
  const ws = new WebSocket(`ws://localhost:8000/ws/${clientId}`);
  const status = document.getElementById("status");
  const messages = document.getElementById("messages");

  ws.onopen = () => {
    status.textContent = `Connected as client #${clientId}`;
    status.style.color = "green";
  };

  ws.onmessage = (event) => {
    // Append each incoming message as a new paragraph
    const p = document.createElement("p");
    p.textContent = event.data;
    messages.appendChild(p);
    // Auto-scroll to the bottom
    messages.scrollTop = messages.scrollHeight;
  };

  ws.onclose = () => {
    status.textContent = "Disconnected — refresh to reconnect";
    status.style.color = "red";
  };

  function sendMessage() {
    const input = document.getElementById("messageInput");
    if (input.value.trim()) {
      ws.send(input.value);  // send to the server
      input.value = "";       // clear the field
    }
  }

  // Send on Enter key — no need to click the button
  document.getElementById("messageInput").addEventListener("keydown", (e) => {
    if (e.key === "Enter") sendMessage();
  });
</script>
</body>
</html>
