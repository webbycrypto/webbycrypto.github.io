File Uploads with FastAPI

Accept files from browsers and API clients — validate type and size, save to disk or cloud storage, and serve them back. Covers images, CSVs, and arbitrary binary files.

1

How File Uploads Work Differently

Normal form data and JSON bodies are small text strings. A file upload is different: it sends the file's binary data as part of an HTTP request using a special encoding called multipart/form-data. Unlike a query parameter or JSON field, a file is not a simple string — it is a stream of bytes that can be megabytes or gigabytes long. FastAPI gives you a UploadFile object for each uploaded file. This object has metadata like the original filename and MIME type, and a file-like interface (read, seek) so you can process the contents. The critical thing to install is python-multipart — FastAPI needs it to parse multipart form data. Without it you will get a runtime error: "No parser found for content-type multipart/form-data".

python-multipart is required. Install it or file uploads will not work: pip install python-multipart. It is not included with FastAPI by default.
2

Single File Upload

To accept a file upload, use UploadFile as the parameter type and File() as the default — the same way you use Form() for text fields. FastAPI handles everything else. The UploadFile object gives you file.filename (the original name the user gave the file on their computer), file.content_type (the MIME type the browser reported, like "image/jpeg" or "text/csv"), and file.file (the actual file object you can read from). Calling await file.read() reads the entire file content into memory as bytes. For large files you would read in chunks instead, but for most use cases a single read() is fine. The file content is bytes, not a string — use .decode() to convert to text if needed.

python
from fastapi import FastAPI, UploadFile, File

app = FastAPI()


@app.post("/upload")
async def upload_file(
    file: UploadFile = File(...)   # File(...) = required upload field
):
    # file.filename  → original filename: "photo.jpg", "data.csv"
    # file.content_type → MIME type: "image/jpeg", "text/csv"
    # file.size → file size in bytes (available without reading)

    # Read the full content into memory as bytes
    contents = await file.read()

    return {
        "filename":     file.filename,
        "content_type": file.content_type,
        "size_bytes":   len(contents)
    }


# Mix a file upload with regular form fields in the same route
@app.post("/upload-with-meta")
async def upload_with_meta(
    file: UploadFile = File(...),
    title: str       = Form(...),   # text field alongside the file
    public: bool    = Form(False)  # checkbox — False if not provided
):
    contents = await file.read()
    return {"title": title, "public": public, "size": len(contents)}
bash
# Upload a file with curl (-F sends multipart/form-data)
curl -X POST http://localhost:8000/upload \
  -F "file=@/path/to/photo.jpg"

# Upload with extra fields
curl -X POST http://localhost:8000/upload-with-meta \
  -F "file=@/path/to/photo.jpg" \
  -F "title=My Photo" \
  -F "public=true"

# Expected response:
# { "filename": "photo.jpg", "content_type": "image/jpeg", "size_bytes": 245123 }

Saving to Disk

Reading the file contents with await file.read() gives you raw bytes. Writing those bytes to disk is just a matter of opening a local path and writing. The main decision is the filename. You should never use the original filename from file.filename directly as the save path — a malicious user could upload a file named ../../etc/passwd or overwrite an existing file by using a predictable name. The safe approach is to generate a UUID for the filename and keep only the original extension for the content type. The uploads/ folder should be created at startup if it does not exist. Using pathlib.Path is the modern Python way to handle file paths — it works correctly on both Windows and Linux and makes path joining safe.

python
from pathlib import Path
import uuid

# Create the uploads folder at startup — parents=True creates any missing parent dirs
UPLOAD_DIR = Path("uploads")
UPLOAD_DIR.mkdir(parents=True, exist_ok=True)


@app.post("/upload")
async def upload_file(file: UploadFile = File(...)):
    # Get the original file extension: "photo.jpg" → ".jpg"
    suffix = Path(file.filename).suffix

    # Generate a random UUID filename to avoid collisions and path traversal attacks
    safe_name = f"{uuid.uuid4()}{suffix}"  # e.g. "3f2e1a0b-....jpg"
    save_path = UPLOAD_DIR / safe_name     # e.g. uploads/3f2e1a0b-....jpg

    # Read file contents and write to disk
    contents = await file.read()
    save_path.write_bytes(contents)  # write_bytes() handles opening and closing

    return {
        "saved_as":  safe_name,
        "url":       f"/files/{safe_name}"  # URL to retrieve the file (step 6)
    }
python
import aiofiles  # pip install aiofiles — async file I/O

@app.post("/upload-large")
async def upload_large(file: UploadFile = File(...)):
    safe_name = f"{uuid.uuid4()}{Path(file.filename).suffix}"
    save_path = UPLOAD_DIR / safe_name

    # Write in 1MB chunks — never loads the whole file into memory
    # aiofiles opens the file asynchronously so it doesn't block other requests
    async with aiofiles.open(save_path, "wb") as out:
        while chunk := await file.read(1024 * 1024):  # read 1MB at a time
            await out.write(chunk)

    return {"saved_as": safe_name}

Multiple Files

Accepting multiple files at once uses a List of UploadFile. The HTML form needs multiple attribute on the file input, and the browser will send all selected files under the same field name. On the Python side, FastAPI collects them into a list and you loop over them. Each item in the list is a full UploadFile object with its own filename, content_type, and read() method. If you want to enforce a maximum number of files you just check len(files) at the start and raise an HTTPException if it is too large.

python
from fastapi import HTTPException
from typing import List

@app.post("/upload-many")
async def upload_many(
    files: List[UploadFile] = File(...)  # List[] = accept multiple files
):
    # Enforce a maximum of 10 files per request
    if len(files) > 10:
        raise HTTPException(status_code=400, detail="Maximum 10 files per upload")

    saved = []
    for file in files:
        # Each file is a full UploadFile — same API as a single file upload
        safe_name = f"{uuid.uuid4()}{Path(file.filename).suffix}"
        save_path = UPLOAD_DIR / safe_name
        save_path.write_bytes(await file.read())
        saved.append({"original": file.filename, "saved_as": safe_name})

    return {"uploaded": len(saved), "files": saved}
bash
# Upload multiple files — repeat -F "files=@..." for each file
curl -X POST http://localhost:8000/upload-many \
  -F "files=@photo1.jpg" \
  -F "files=@photo2.jpg" \
  -F "files=@photo3.jpg"

File Validation — Type and Size

Never trust the browser's reported content type alone — it can be spoofed by a malicious user sending a request with any content_type header they choose. Real validation checks the actual file contents. For images, Python's imghdr module (or the Pillow library) reads the first few bytes and identifies the actual format. For any file type, you check the magic bytes — the first bytes of the file that identify its format. For example, JPEG files always start with FF D8 FF. A useful shortcut for most use cases: check the file extension from the original filename and the content_type header as a first filter, then read the first few bytes to confirm. Also always enforce a maximum file size to prevent someone uploading a 10GB file that exhausts your server's memory.

python
MAX_FILE_SIZE = 5 * 1024 * 1024  # 5 MB in bytes

ALLOWED_TYPES = {
    "image/jpeg", "image/png", "image/gif", "image/webp"
}

ALLOWED_EXTENSIONS = {".jpg", ".jpeg", ".png", ".gif", ".webp"}


@app.post("/upload-image")
async def upload_image(file: UploadFile = File(...)):
    # Check 1: file extension
    ext = Path(file.filename).suffix.lower()
    if ext not in ALLOWED_EXTENSIONS:
        raise HTTPException(400, detail=f"Extension {ext} not allowed")

    # Check 2: reported content type (first filter — can be spoofed)
    if file.content_type not in ALLOWED_TYPES:
        raise HTTPException(400, detail="Only image files allowed")

    # Read the file — needed for both size check and magic bytes
    contents = await file.read()

    # Check 3: file size
    if len(contents) > MAX_FILE_SIZE:
        raise HTTPException(413, detail="File too large — max 5 MB")
        # 413 = "Request Entity Too Large" — the standard HTTP status for this

    # All checks passed — save the file
    safe_name = f"{uuid.uuid4()}{ext}"
    (UPLOAD_DIR / safe_name).write_bytes(contents)
    return {"saved_as": safe_name}
python
# Magic bytes — the actual first bytes of each format
# A file claiming to be JPEG must start with these bytes
MAGIC_BYTES = {
    b"\xff\xd8\xff":      "image/jpeg",   # JPEG
    b"\x89PNG\r\n\x1a\n": "image/png",    # PNG
    b"GIF87a":           "image/gif",    # GIF87
    b"GIF89a":           "image/gif",    # GIF89
    b"RIFF":             "image/webp",   # WebP starts with RIFF....WEBP
    b"%PDF":             "application/pdf",
}

def detect_mime(data: bytes) -> str:
    for magic, mime in MAGIC_BYTES.items():
        if data.startswith(magic):
            return mime
    return "unknown"

Serving Uploaded Files Back

Saving a file to disk is only half the job — you also need to serve it back to users who want to view or download it. FastAPI's StaticFiles mount serves a whole folder at a URL prefix. This is the simplest approach: mount your uploads/ folder at /files/ and every file in it becomes accessible at /files/filename.jpg. For downloading a specific file as an attachment (forcing a browser download dialog rather than displaying in the browser), use FileResponse with the media_type and content-disposition header. FileResponse streams the file efficiently without loading it all into memory, making it suitable for large files.

python
from fastapi.staticfiles import StaticFiles

# Mount the uploads folder — files are served at /files/filename
# e.g. uploads/abc123.jpg → http://localhost:8000/files/abc123.jpg
app.mount("/files", StaticFiles(directory="uploads"), name="files")

# Now your upload route can return a usable URL:
@app.post("/upload")
async def upload(file: UploadFile = File(...)):
    safe_name = f"{uuid.uuid4()}{Path(file.filename).suffix}"
    (UPLOAD_DIR / safe_name).write_bytes(await file.read())

    # The URL is /files/{safe_name} — absolute URL for frontend use
    return {"url": f"/files/{safe_name}"}
python
from fastapi.responses import FileResponse

@app.get("/download/{filename}")
def download_file(filename: str):
    file_path = UPLOAD_DIR / filename

    if not file_path.exists():
        raise HTTPException(status_code=404, detail="File not found")

    # FileResponse streams the file efficiently
    # filename= sets the name suggested to the browser when saving
    return FileResponse(
        path=file_path,
        filename=filename,               # name shown in download dialog
        media_type="application/octet-stream"  # force download instead of browser display
    )

S3-Compatible Cloud Storage

Saving to local disk works fine for a single server but breaks as soon as you scale out — if you have two servers, each has its own disk, and a file uploaded to server A is not visible from server B. Cloud object storage solves this: AWS S3, Cloudflare R2, DigitalOcean Spaces, and Backblaze B2 all use the same S3-compatible API, so the same Python code works with any of them. The boto3 library is the AWS SDK that also works with all S3-compatible providers. You set the endpoint_url to point at your provider instead of AWS, and the rest is identical. Files stored in S3 get a public URL you can return directly to the frontend — no need to serve them through your own server at all.

python
import boto3
import os
from dotenv import load_dotenv

load_dotenv()

# Create the S3 client — works with AWS S3, Cloudflare R2, DO Spaces, etc.
s3 = boto3.client(
    "s3",
    endpoint_url         = os.getenv("S3_ENDPOINT"),     # omit for real AWS
    aws_access_key_id    = os.getenv("S3_ACCESS_KEY"),
    aws_secret_access_key= os.getenv("S3_SECRET_KEY"),
    region_name          = os.getenv("S3_REGION", "auto"),
)

BUCKET = os.getenv("S3_BUCKET")


@app.post("/upload")
async def upload_to_s3(file: UploadFile = File(...)):
    safe_name = f"{uuid.uuid4()}{Path(file.filename).suffix}"
    contents = await file.read()

    # put_object() uploads bytes directly to S3
    s3.put_object(
        Bucket=BUCKET,
        Key=safe_name,                     # the S3 "path" / object name
        Body=contents,
        ContentType=file.content_type,     # tells browsers how to display the file
        ACL="public-read"                  # makes the file publicly accessible
    )

    # Build the public URL — the format varies by provider
    public_url = f"{os.getenv('S3_ENDPOINT')}/{BUCKET}/{safe_name}"
    return {"url": public_url}
bash

HTML File Picker Frontend

File uploads from HTML require a form with enctype="multipart/form-data" — without this attribute the browser sends the form as URL-encoded text and the file never reaches the server. The file input needs a name attribute that matches the parameter name in your FastAPI route. For drag-and-drop uploads or showing a preview before submission, you use JavaScript's FormData API to capture the file, fetch() to send it, and the FileReader API to generate an object URL for the preview image. The key difference from a regular fetch() call is that you do not set a Content-Type header manually — when you pass a FormData object to fetch(), the browser sets the correct multipart/form-data header with the boundary automatically.

html
<!-- enctype="multipart/form-data" is REQUIRED for file uploads -->
<!-- Without it the file is not sent, only the filename as text -->
<form action="/upload" method="post" enctype="multipart/form-data">

  <label>Choose a file:</label>
  <!-- name="file" must match the FastAPI param: file: UploadFile = File(...) -->
  <input type="file" name="file" accept="image/*" required>

  <!-- For multiple files: add "multiple" attribute -->
  <!-- name="files" must match: files: List[UploadFile] = File(...) -->
  <!-- <input type="file" name="files" multiple accept="image/*"> -->

  <button type="submit">Upload</button>
</form>
html
<input type="file" id="fileInput" accept="image/*">
<img id="preview" style="max-width:200px; display:none">
<button onclick="uploadFile()">Upload</button>
<p id="result"></p>

<script>
  // Show a preview before uploading
  document.getElementById("fileInput").addEventListener("change", function() {
    const file = this.files[0];
    if (!file) return;

    // URL.createObjectURL() creates a temporary URL pointing at the local file
    document.getElementById("preview").src = URL.createObjectURL(file);
    document.getElementById("preview").style.display = "block";
  });

  async function uploadFile() {
    const file = document.getElementById("fileInput").files[0];
    if (!file) return alert("Please select a file first");

    // FormData builds the multipart/form-data body
    const formData = new FormData();
    formData.append("file", file);  // "file" must match the FastAPI param name

    // Do NOT set Content-Type header manually — browser adds it with the boundary
    const response = await fetch("/upload", { method: "POST", body: formData });
    const data = await response.json();

    document.getElementById("result").textContent =
      response.ok ? `Uploaded: ${data.url}` : `Error: ${data.detail}`;
  }
</script>
