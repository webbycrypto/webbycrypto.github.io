Jinja2 Templates with FastAPI

Render HTML pages on the server instead of returning JSON. Covers setup, variables, filters, control flow, template inheritance, forms, query results, URL building, and flash messages.

1

Templates vs JSON APIs

A JSON API returns raw data and expects a separate frontend (React, Vue, a mobile app) to turn it into a page. Server-rendered templates do the opposite: FastAPI builds the complete HTML page and sends it directly to the browser. Templates are simpler to start with because there is no separate frontend project to maintain.

python
# JSON API — browser gets raw data, must render it separately
@app.get("/score")
async def get_score():
    return {"name": "Alice", "score": 95}
# → browser receives: {"name": "Alice", "score": 95}
# → browser must use JavaScript to turn this into visible HTML
python
from fastapi import FastAPI, Request
from fastapi.templating import Jinja2Templates

app = FastAPI()
templates = Jinja2Templates(directory="templates")

# Template route — browser gets a complete HTML page
@app.get("/score")
async def score_page(request: Request):
    return templates.TemplateResponse(
        "score.html",                              # template file to render
        {"request": request, "name": "Alice", "score": 95}  # variables for the template
    )
html
<!-- templates/score.html — {{ }} is replaced by FastAPI -->
<!DOCTYPE html>
<html>
<head><title>Score</title></head>
<body>
  <h1>Hello, {{ name }}!</h1>        <!-- outputs: Hello, Alice! -->
  <p>Your score is {{ score }}.</p>  <!-- outputs: Your score is 95. -->
</body>
</html>

Setup

Jinja2 needs to know which folder to look for template files. You create a Jinja2Templates object pointing at your templates/ directory. Static files (CSS, images) are served separately with StaticFiles mounted at a URL prefix.

text
myapp/
  main.py
  templates/         ← Jinja2 looks here for .html files
    base.html
    index.html
    items.html
  static/            ← served at /static/...
    style.css
    logo.png
python
from fastapi import FastAPI, Request
from fastapi.templating import Jinja2Templates
from fastapi.staticfiles import StaticFiles

app = FastAPI()

templates = Jinja2Templates(directory="templates")   # where .html files live
app.mount(
    "/static",                                       # URL prefix
    StaticFiles(directory="static"),               # folder on disk
    name="static"                                    # name used in url_for()
)
3

Your First Template

Every Jinja route returns a TemplateResponse. The first argument is the template filename relative to your templates/ directory. The second argument is a dictionary called the context — it contains all the variables the template can use. You must always include "request": request in the context; FastAPI requires it.

python
@app.get("/hello")
async def hello(request: Request):
    return templates.TemplateResponse(
        "hello.html",                          # template filename inside templates/
        {
            "request": request,                 # always required by FastAPI
            "name": "Alice",                    # variable available as {{ name }}
            "score": 95,                       # variable available as {{ score }}
        }
    )
html
<!DOCTYPE html>
<html>
<head>
  <title>Hello</title>
  <style>
    body { font-family: sans-serif; padding: 20px; }
  </style>
</head>
<body>
  <h1>Hello, {{ name }}!</h1>        <!-- replaced with "Alice" -->
  <p>Your score is {{ score }}.</p>  <!-- replaced with 95 -->
</body>
</html>

Variables and Filters

Variables use double curly braces: {{ variable }}. To access a property you write {{ user.name }} — Jinja2 handles both object attributes and dict keys with the same dot syntax. Filters modify the value before displaying it; you chain them with a pipe character. Jinja2 has dozens of built-in filters.

html
<!-- simple variable -->
<p>{{ name }}</p>

<!-- object attribute -->
<p>{{ user.email }}</p>

<!-- list index -->
<p>{{ items[0] }}</p>

<!-- round to 2 decimal places -->
<p>${{ price | round(2) }}</p>

<!-- uppercase -->
<p>{{ title | upper }}</p>

<!-- count items in a list -->
<p>{{ items | length }} results</p>

<!-- show fallback if value is empty -->
<p>{{ description | default("No description") }}</p>

<!-- cut off long text after 100 chars -->
<p>{{ bio | truncate(100) }}</p>
text
Filter           What it does                   Example
─────────────────────────────────────────────────────────
upper            ALL CAPS                        {{ name | upper }}
lower            all lowercase                  {{ name | lower }}
title            Title Case                     {{ name | title }}
length           count items                    {{ list | length }}
round(n)         round to n decimal places      {{ 3.14159 | round(2) }}
default(val)     use val if variable is empty   {{ bio | default("n/a") }}
truncate(n)      cut text after n characters    {{ text | truncate(80) }}
join(", ")       join a list into a string      {{ tags | join(", ") }}
first            first item of a list           {{ items | first }}
last             last item of a list            {{ items | last }}

Control Flow

Jinja2 uses {% %} tags for logic. These tags do not produce any output themselves — they only control which HTML gets rendered. Always close every tag: {% if %} needs {% endif %}, and {% for %} needs {% endfor %}.

html
{% if user.is_logged_in %}
  <p>Welcome back, {{ user.name }}!</p>
{% elif user.is_guest %}
  <p>Browsing as guest.</p>
{% else %}
  <p><a href="/login">Log in</a></p>
{% endif %}
html
{% if items %}
  <ul>
    {% for item in items %}
      <li>
        {{ loop.index }}. {{ item.name }}     <!-- loop.index starts at 1 -->
        — ${{ item.price | round(2) }}
        {% if loop.first %} ⭐ Featured{% endif %}   <!-- true on first item -->
      </li>
    {% endfor %}
  </ul>
{% else %}
  <p>No items found.</p>    <!-- shown when items list is empty -->
{% endif %}

<!-- loop special variables: -->
<!-- loop.index    → current position, starting at 1  -->
<!-- loop.index0   → current position, starting at 0  -->
<!-- loop.first    → True on the first item            -->
<!-- loop.last     → True on the last item             -->

Template Inheritance

Copying the same header and footer HTML into every page is tedious and error-prone. Inheritance lets you define a base template with the shared layout and named placeholder blocks. Each page template extends it and fills in only the blocks that change, so updating the nav bar in one file updates every page.

html
<!DOCTYPE html>
<html>
<head>
  <title>{% block title %}My App{% endblock %}</title>   <!-- child can override -->
  <style>
    body { font-family: sans-serif; padding: 20px; max-width: 800px; margin: 0 auto; }
    nav a { margin-right: 12px; }
  </style>
</head>
<body>
  <nav>
    <a href="/">Home</a>
    <a href="/about">About</a>
  </nav>
  <hr>
  {% block content %}{% endblock %}   <!-- child fills this in -->
  <hr>
  <footer>My App &copy; 2024</footer>
</body>
</html>
html
{% extends "base.html" %}    <!-- must be the very first line -->

{% block title %}Products{% endblock %}   <!-- overrides the <title> tag -->

{% block content %}         <!-- everything here goes into the base template's block -->
  <h1>All Products</h1>
  <ul>
    {% for p in products %}
      <li>{{ p.name }} — ${{ p.price | round(2) }}</li>
    {% endfor %}
  </ul>
{% endblock %}

Forms and POST

HTML forms send data to your FastAPI route when the user clicks submit. GET forms put the values in the URL as query parameters. POST forms send data in the request body — use POST for anything that creates or changes data. After a successful POST you should redirect the user so refreshing the browser does not resubmit the form.

python
from fastapi import Form
from fastapi.responses import RedirectResponse

# GET — show the empty form
@app.get("/add-item")
async def add_item_form(request: Request):
    return templates.TemplateResponse("add_item.html", {"request": request})

# POST — receive form data
@app.post("/add-item")
async def add_item(
    name:  str   = Form(...),   # must match name="name" in the HTML input
    price: float = Form(...),   # must match name="price" in the HTML input
):
    # save to database here ...
    return RedirectResponse("/items", status_code=303)  # 303 = redirect after POST
html
{% extends "base.html" %}
{% block title %}Add Item{% endblock %}
{% block content %}
<h1>Add Item</h1>
<form method="POST" action="/add-item">
  <label>
    Name:<br>
    <input type="text" name="name" required>   <!-- name= must match Form() param -->
  </label><br><br>
  <label>
    Price:<br>
    <input type="number" name="price" step="0.01" required>
  </label><br><br>
  <button type="submit">Add Item</button>
</form>
{% endblock %}

Passing Query Results

You query your database in the route function and pass the results to the template as a list. Jinja2 does not know or care whether the items came from a database, a file, or a hardcoded list — it just loops over whatever you pass. Include any extra values the template needs, like a count or a title, in the context dictionary.

python
from sqlalchemy.orm import Session
from fastapi import Depends

@app.get("/items")
async def list_items(request: Request, db: Session = Depends(get_db)):
    items = db.query(Item).all()              # list of Item objects from the database
    return templates.TemplateResponse(
        "items.html",
        {
            "request": request,
            "items":   items,           # the list the template will loop over
            "count":   len(items),      # extra value for the heading
        }
    )
html
{% extends "base.html" %}
{% block title %}Items{% endblock %}
{% block content %}
<h1>Items ({{ count }} total)</h1>
{% if items %}
  <table>
    <tr><th>Name</th><th>Price</th></tr>
    {% for item in items %}
    <tr>
      <td><a href="/items/{{ item.id }}">{{ item.name }}</a></td>
      <td>${{ item.price | round(2) }}</td>
    </tr>
    {% endfor %}
  </table>
{% else %}
  <p>No items yet. <a href="/add-item">Add one</a>.</p>
{% endif %}
{% endblock %}

URL Building

Hard-coding URLs like /items/42 in your templates breaks if you ever move the app or rename a route. url_for() generates URLs from route function names so they stay correct even if you change the URL structure. Use it for links, form actions, and static file references.

html
<!-- link to a route by its function name -->
<a href="{{ url_for('list_items') }}">All Items</a>
<!-- generates: /items -->

<!-- link to a route with a path parameter -->
<a href="{{ url_for('item_detail', item_id=item.id) }}">{{ item.name }}</a>
<!-- generates: /items/42 -->

<!-- load a static file (CSS, image, JS) -->
<link rel="stylesheet" href="{{ url_for('static', path='style.css') }}">
<!-- generates: /static/style.css -->

<!-- use url_for in a form action too -->
<form method="POST" action="{{ url_for('add_item') }}">...</form>
python
# The function name IS the route name used in url_for()

@app.get("/items")
async def list_items(request: Request, ...):   # url_for('list_items') → /items
    ...

@app.get("/items/{item_id}")
async def item_detail(item_id: int, ...):      # url_for('item_detail', item_id=5) → /items/5
    ...

@app.post("/add-item")
async def add_item(...):                       # url_for('add_item') → /add-item
    ...

# 'static' is the name you gave to app.mount()
# url_for('static', path='style.css') → /static/style.css

Flash Messages

After a successful form POST you redirect the user. But the redirect loses any message you want to show, like "Item saved." Flash messages solve this by storing a short message in the session before the redirect, then reading and clearing it on the next page load. The itsdangerous package signs the session data so users cannot tamper with it.

python
from starlette.middleware.sessions import SessionMiddleware

# Add once, near the top of main.py
app.add_middleware(SessionMiddleware, secret_key="change-me-in-production")

@app.post("/add-item")
async def add_item(request: Request, name: str = Form(...)):
    # ... save item to database ...
    request.session["flash"] = f"'{name}' was added successfully."  # store message
    return RedirectResponse("/items", status_code=303)                  # redirect
python
@app.get("/items")
async def list_items(request: Request, db: Session = Depends(get_db)):
    flash = request.session.pop("flash", None)  # read and remove in one step
    items = db.query(Item).all()
    return templates.TemplateResponse("items.html", {
        "request": request,
        "items":   items,
        "flash":   flash,   # None if no message is waiting
    })

# In the template:
# {% if flash %}
#   <p style="color:green; border:1px solid green; padding:8px;">{{ flash }}</p>
# {% endif %}

What's Next

You now know how to render any data from your database as a complete HTML page, build forms, chain templates together with inheritance, and show feedback messages across redirects.

Auto-escaping is on by default. Jinja2 automatically escapes <, >, &, and " in all variables. If a user submits <script>alert(1)</script> as their name, it displays as plain text — not code. This protects against XSS attacks without any extra work. To render raw HTML you control intentionally, use {{ content | safe }}.
HTMX for dynamic updates. HTMX lets you update parts of your Jinja-rendered page without a full page reload, using simple HTML attributes like hx-get and hx-target. You keep writing server-rendered templates — HTMX just swaps in the new HTML fragment. See the HTMX guide for how to combine it with the patterns from this guide.
Sending HTML emails with Jinja2. The same templates folder works for email bodies. Use templates.get_template("email_welcome.html").render({"name": name, "link": link}) to produce an HTML string, then pass it to your email service. You get the same inheritance and filter features as in web templates.
