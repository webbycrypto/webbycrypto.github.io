HTTPS with Certbot + Let's Encrypt

Get a free TLS certificate from Let's Encrypt, configure Nginx to serve HTTPS, and set up auto-renewal. The whole process takes about 5 minutes once your domain is pointed at the server.

1

What HTTPS Is (and Why It Matters)

HTTPS encrypts traffic between the browser and your server. Without it, every password, JWT token, and piece of data travels in plaintext — readable by anyone on the same network. Browsers show a "Not Secure" warning for HTTP sites, and modern features (cookies with Secure flag, service workers, geolocation) require HTTPS.

Let's Encrypt: A free, automated certificate authority. Certbot is the official client that requests the certificate, proves you own the domain, and configures Nginx automatically. Certificates last 90 days and auto-renew. Completely free.
2

Point Your Domain at the Server

Before Certbot can issue a certificate, Let's Encrypt needs to verify you control the domain by making an HTTP request to it. That means the domain must already be pointing to your server's IP.

text — DNS records to add
In your domain registrar's DNS settings, add:

  Type   Name    Value
  A      @       YOUR_SERVER_IP     (for yourdomain.com)
  A      www     YOUR_SERVER_IP     (for www.yourdomain.com)

Where to do this:
  Namecheap: Domain List → Manage → Advanced DNS
  GoDaddy:   My Products → DNS → Manage DNS
  Cloudflare: DNS → Records

DNS propagation takes 1–60 minutes. Check with:
  nslookup yourdomain.com
  # Should return your server IP

Or: dig yourdomain.com +short
Must point before running Certbot. If the domain doesn't resolve to your server when you run certbot, the certificate request will fail.

4

Get a Certificate

One command. Certbot handles domain verification, certificate download, Nginx config update, and reloading Nginx.

bash
# Replace yourdomain.com with your actual domain
sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com

# Certbot will ask:
#   1. Your email (for renewal reminders and urgent notices)
#   2. Agree to terms of service
#   3. Whether to redirect HTTP to HTTPS (choose Yes = option 2)

# After it finishes:
#   - Certificate stored in /etc/letsencrypt/live/yourdomain.com/
#   - Nginx config updated with ssl_certificate lines
#   - Nginx reloaded automatically

# Test: https://yourdomain.com should now work with a padlock
nginx — what certbot adds to your config
server {
    server_name yourdomain.com www.yourdomain.com;

    location / {
        proxy_pass http://127.0.0.1:8000;
        # ... headers ...
    }

    # Certbot adds these lines automatically:
    listen 443 ssl;
    ssl_certificate     /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;
}

server {
    # Certbot also adds this redirect block:
    if ($host = yourdomain.com) { return 301 https://$host$request_uri; }
    listen 80;
    server_name yourdomain.com www.yourdomain.com;
    return 404;
}
5

Auto-Renewal

Let's Encrypt certificates expire after 90 days. Certbot installs a systemd timer (or cron job) that automatically renews them. Test the renewal process works.

bash
# Test the renewal process (dry run — doesn't actually renew)
sudo certbot renew --dry-run
# Should say "Congratulations, all simulated renewals succeeded"

# Check the auto-renewal timer is active
sudo systemctl status certbot.timer
# Should show "active (waiting)"
# Certbot runs twice daily and renews if expiry is within 30 days

# See all installed certificates and their expiry dates
sudo certbot certificates
6

Verify + Check Your HTTPS

text
1. Visit https://yourdomain.com in your browser
   → Padlock icon in the address bar
   → No "Not Secure" warning

2. Visit http://yourdomain.com
   → Should redirect to https:// automatically (Certbot added this)

3. Check certificate details
   → Click the padlock → Certificate → inspect the issuer (Let's Encrypt)
      and expiry date (90 days from issue)

4. Run an SSL test (optional but useful):
   https://www.ssllabs.com/ssltest/analyze.html?d=yourdomain.com
   → Should score A or A+
