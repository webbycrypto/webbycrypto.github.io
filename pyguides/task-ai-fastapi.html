Task / Note App with UI + AI Chat

Build on the CRUD fundamentals: add JSON file persistence so notes survive restarts, build a two-column UI with a task list and a live AI chat panel, and wire it all to OpenAI or the Claude API with no JavaScript required.

1

What We're Building

This guide extends the FastAPI CRUD pattern into a real mini-app with two parts running side by side on one page: a note list on the left where you add, complete, and delete notes, and an AI chat panel on the right where you can type a question or click "Summarise my notes" to get an AI-generated summary. Everything runs through FastAPI with Jinja2 templates — no JavaScript frameworks, no React, no fetch() calls from the browser.

What this teaches you: Persisting data between restarts with a JSON file, building multi-section HTML UIs with Jinja2, calling an AI API from a FastAPI route with httpx, and managing a conversation without JavaScript.
2

File Structure

Keep it simple — one Python file, one template, one CSS file, one data file, and a .env for your API key.

text
my-task-app/
├── main.py             ← FastAPI routes + AI call
├── notes.json          ← created automatically on first run
├── .env                ← AI API key (never commit this)
├── templates/
│   └── index.html      ← two-column UI (Jinja2 template)
└── static/
    └── style.css       ← all the CSS
Why a JSON file? In the CRUD guide, notes lived in db = {} in memory. That dict disappears every time you restart uvicorn. A JSON file on disk persists forever — no database setup required. For a production app you'd use SQLite or PostgreSQL, but JSON is perfect for learning.

Persisting Notes (JSON File)

Two helper functions replace the in-memory db = {} dict. load_notes() reads the JSON file from disk every time a route needs the data. save_notes() writes the whole list back after any change. This is the simplest possible persistence without a database.

python
import json, os, time
from pathlib import Path

# Path to the data file — sits next to main.py
DATA_FILE = Path("notes.json")

def load_notes() -> list:
    """Read notes from disk. Return empty list if file doesn't exist yet."""
    if not DATA_FILE.exists():
        return []
    with open(DATA_FILE) as f:
        return json.load(f)   # parse JSON → Python list of dicts

def save_notes(notes: list):
    """Write the full list back to disk as JSON."""
    with open(DATA_FILE, "w") as f:
        json.dump(notes, f, indent=2)   # indent=2 makes the file human-readable

# Each note is a plain dict:
# {"id": 1, "text": "Buy milk", "done": False, "created": 1717000000.0}
What is Path? pathlib.Path is Python's built-in tool for working with file paths. Path("notes.json").exists() checks if the file is there. It's cleaner than the old os.path.exists() style.

Notes CRUD Routes

Four routes handle everything. Each one loads the notes from the JSON file, makes a change, saves the file back, and redirects to GET / so the page refreshes with the latest data. This is the same Post-Redirect-Get pattern from the CRUD guide — it prevents the browser resubmitting the form if you hit refresh.

python
from fastapi import FastAPI, Form, Request
from fastapi.responses import HTMLResponse, RedirectResponse
from fastapi.staticfiles import StaticFiles
from fastapi.templating import Jinja2Templates

app = FastAPI()
app.mount("/static", StaticFiles(directory="static"), name="static")
templates = Jinja2Templates(directory="templates")

# ── READ: serve the page with the current notes ──────────────────
@app.get("/", response_class=HTMLResponse)
def index(request: Request, chat_reply: str = "", chat_history: str = "[]"):
    notes = load_notes()
    return templates.TemplateResponse("index.html", {
        "request": request,
        "notes": notes,
        "chat_reply": chat_reply,
        "chat_history": chat_history,  # JSON string of past messages
    })

# ── CREATE: add a new note ────────────────────────────────────────
@app.post("/notes/create")
def create_note(text: str = Form(...)):
    notes = load_notes()
    new_id = (notes[-1]["id"] + 1) if notes else 1   # next ID
    notes.append({"id": new_id, "text": text, "done": False, "created": time.time()})
    save_notes(notes)
    return RedirectResponse("/", status_code=303)

# ── TOGGLE: flip done/undone ──────────────────────────────────────
@app.post("/notes/toggle")
def toggle_note(note_id: int = Form(...)):
    notes = load_notes()
    for n in notes:
        if n["id"] == note_id:
            n["done"] = not n["done"]   # flip True↔False
    save_notes(notes)
    return RedirectResponse("/", status_code=303)

# ── DELETE: remove a note ─────────────────────────────────────────
@app.post("/notes/delete")
def delete_note(note_id: int = Form(...)):
    notes = load_notes()
    notes = [n for n in notes if n["id"] != note_id]   # keep everything except this ID
    save_notes(notes)
    return RedirectResponse("/", status_code=303)
List comprehension for delete: [n for n in notes if n["id"] != note_id] builds a new list that includes every note except the one being deleted. It's the Python equivalent of WHERE id != X in SQL.

Jinja2 Recap

Two Jinja2 patterns make the notes list dynamic. The {% if note.done %} block adds a CSS class to a card so you can style completed notes differently. The button label also changes between "Done" and "Undo" based on the same flag.

html + jinja2
<!-- Output a value -->
{{ note.text }}          <!-- prints the text key from the dict -->
{{ note.id }}            <!-- prints the id -->

<!-- Loop -->
{% for note in notes %}
  ...one card per note...
{% endfor %}

<!-- Conditional class on a card -->
<div class="note-card {% if note.done %}done{% endif %}">
<!-- adds class "done" when note["done"] is True -->

<!-- Conditional button label -->
{% if note.done %}Undo{% else %}Done{% endif %}

<!-- Empty state -->
{% if notes %}
  ...loop...
{% else %}
  <p>No notes yet.</p>
{% endif %}
Remember: {{ }} outputs a value. {% %} is logic (loops, if/else). The browser never sees these tags — Python replaces them with real HTML before sending the page.

What is an AI API?

An AI API is just a URL you POST text to and get text back. You send a JSON payload with a model name and a list of messages. The model returns its reply as JSON. That's it. The "AI" is entirely on their servers — you're just making an HTTP request the same way you'd call a weather API or a CRM.

json — what you send
POST https://api.openai.com/v1/chat/completions
Authorization: Bearer YOUR_API_KEY

{
  "model": "gpt-4o-mini",
  "messages": [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user",   "content": "Summarise my three notes for today."}
  ]
}
json — Claude (Anthropic)
POST https://api.anthropic.com/v1/messages
x-api-key: YOUR_API_KEY
anthropic-version: 2023-06-01

{
  "model": "claude-haiku-4-5",
  "max_tokens": 1024,
  "messages": [
    {"role": "user", "content": "Summarise my three notes for today."}
  ]
}
Never hardcode your API key. If you put api_key = "sk-..." directly in your Python file and push it to GitHub, bots will find it within minutes and run up charges on your account. Always load it from a .env file — see the next step.

Setting Up .env

A .env file stores secrets outside your code. python-dotenv reads it into environment variables so Python can access them with os.getenv(). Add .env to your .gitignore so it never gets committed.

.env

The /chat Route

The chat route receives the user's message from the form, builds a list of messages including any previous conversation history, calls the AI API, and redirects back to GET / with the reply and history passed as query parameters — a no-JS way to carry state between page loads.

python
import httpx, json
from urllib.parse import quote   # encode strings safely for URLs

@app.post("/chat")
def chat(
    message:     str = Form(...),
    history_raw: str = Form("[]"),  # JSON string of past messages, default empty
):
    # Parse the history back into a Python list
    history = json.loads(history_raw)

    # Add the new user message to the list
    history.append({"role": "user", "content": message})

    # Call the AI API — see Step 11 for the call_openai() function
    reply = call_ai(history)

    # Add the AI reply to history so the next message has context
    history.append({"role": "assistant", "content": reply})

    # Redirect back to the page, passing reply and history as query params
    encoded_reply   = quote(reply)
    encoded_history = quote(json.dumps(history))
    return RedirectResponse(
        f"/?chat_reply={encoded_reply}&chat_history={encoded_history}",
        status_code=303
    )
Why quote()? The reply and history need to be passed in a URL. Spaces, quotes, and special characters would break the URL. urllib.parse.quote() encodes them safely (e.g. " " → %20). FastAPI automatically decodes them when they arrive at GET /.

Calling OpenAI (or Claude)

The call_ai() function makes the HTTP request to whichever AI API you're using. Both providers accept the same messages list format — only the URL, headers, and how you extract the reply text differ slightly.

python — call_ai() for OpenAI
def call_ai(messages: list) -> str:
    """Send messages to OpenAI, return the reply text."""
    response = httpx.post(
        "https://api.openai.com/v1/chat/completions",
        headers={
            "Authorization": f"Bearer {AI_KEY}",
            "Content-Type": "application/json",
        },
        json={
            "model": "gpt-4o-mini",
            "messages": [{"role": "system", "content": "You are a helpful assistant."}]
                       + messages,
        },
        timeout=30,
    )
    response.raise_for_status()   # raises an error if the API returned 4xx/5xx
    data = response.json()
    return data["choices"][0]["message"]["content"]   # extract reply text
python — call_ai() for Claude
def call_ai(messages: list) -> str:
    """Send messages to Claude, return the reply text."""
    response = httpx.post(
        "https://api.anthropic.com/v1/messages",
        headers={
            "x-api-key": AI_KEY,
            "anthropic-version": "2023-06-01",
            "Content-Type": "application/json",
        },
        json={
            "model": "claude-haiku-4-5",
            "max_tokens": 1024,
            "messages": messages,
        },
        timeout=30,
    )
    response.raise_for_status()
    data = response.json()
    return data["content"][0]["text"]   # Claude's response shape is slightly different
Why raise_for_status()? If the API returns a 401 Unauthorized (bad key), 429 Too Many Requests, or any error, this line throws a Python exception instead of silently giving you broken data. Always include it on API calls.

The Chat UI

The right-column chat panel shows conversation history as styled bubbles, then a text input. The conversation history is passed back to Python as a hidden field containing a JSON string — no JavaScript needed to maintain state between page loads.

html + jinja2
<section class="chat-panel">
  <h2>AI Chat</h2>

  <!-- Show conversation history as bubbles -->
  <div class="chat-history">
    {% set history = chat_history | from_json %}
    {% for msg in history %}
      <div class="bubble {{ msg.role }}">{{ msg.content }}</div>
    {% endfor %}
    {% if not history %}
      <p style="color:#aaa;font-size:.9rem">Ask me anything about your notes...</p>
    {% endif %}
  </div>

  <!-- Chat form -->
  <form method="post" action="/chat" class="chat-form">

    <!-- history_raw carries the full conversation back to Python invisibly -->
    <input type="hidden" name="history_raw" value='{{ chat_history }}'>

    <input type="text" name="message" placeholder="Type a message..." required>
    <button type="submit">Send</button>
  </form>
</section>
| from_json: Jinja2 doesn't have a built-in JSON parser, so you need to register one. Add this to main.py: templates.env.filters["from_json"] = json.loads — this makes | from_json available in all templates.

Connecting Notes to AI

The "Summarise my notes" button is a separate form that pre-builds the message before submitting. It posts to /chat with a message that lists all the current note texts. The AI receives them as context and replies with a summary or priority suggestions.

html + jinja2
<!-- Above the chat form, inside .chat-panel -->
<form method="post" action="/summarise">
  <!-- Pass note IDs so the server can fetch the latest texts -->
  <input type="hidden" name="history_raw" value='{{ chat_history }}'>
  <button type="submit" class="btn-summarise">
    ✨ Summarise my notes
  </button>
</form>
python — /summarise route
@app.post("/summarise")
def summarise(history_raw: str = Form("[]")):
    notes = load_notes()
    if not notes:
        reply = "You have no notes yet!"
    else:
        # Build a message that lists all note texts
        note_lines = "\n".join(
            f"- {'[done] ' if n['done'] else ''}{n['text']}"
            for n in notes
        )
        prompt = f"Here are my current notes:\n{note_lines}\n\nPlease summarise them and suggest which ones to prioritise."
        history = json.loads(history_raw)
        history.append({"role": "user", "content": prompt})
        reply = call_ai(history)
        history.append({"role": "assistant", "content": reply})

    encoded_reply   = quote(reply)
    encoded_history = quote(json.dumps(history if notes else []))
    return RedirectResponse(
        f"/?chat_reply={encoded_reply}&chat_history={encoded_history}",
        status_code=303
    )

What's Next

You've built a persistent task app with a real AI integration — without a database or JavaScript. Here are the natural next steps to level it up:

Swap JSON for a real database: Replace load_notes() / save_notes() with SQLAlchemy + SQLite. The routes don't change — only the two helper functions. See the SQLAlchemy docs: pip install sqlalchemy.
Add user accounts: Right now all notes are shared. Add a publisher_id (or just a session cookie) to each note dict so each user sees only their own notes.
Stream AI responses: Instead of waiting for the full reply, use FastAPI's StreamingResponse with OpenAI's streaming API so text appears word by word. Requires a little JavaScript (EventSource or fetch with a readable stream).
Tags and filtering: Add a tags field to each note (list of strings). Add a GET /?tag=work query parameter that filters the notes list before passing it to the template.
