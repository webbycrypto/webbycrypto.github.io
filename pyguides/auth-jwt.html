JWT Access Tokens

Make your login route return a signed token that proves who the user is on every subsequent request — without hitting the database each time. Covers token creation, decoding, FastAPI's Depends for route protection, and how to test it in the /docs UI.

1

What is a JWT?

A JWT (JSON Web Token) is a compact string the server gives to the client after a successful login. The client sends it back with every request, and the server uses it to know who's asking — without querying the database. It has three parts separated by dots: header.payload.signature.

text
HEADER    — algorithm used to sign (e.g. HS256)
PAYLOAD   — the data: user_id, email, expiry timestamp
SIGNATURE — HMAC of header+payload using your SECRET_KEY

The signature is what makes it trustworthy. Only your server
knows the SECRET_KEY, so only your server can create a valid
signature. Anyone can READ the payload (it's just base64),
but no one can FORGE a token without the key.

This means: never put secrets in the payload.
Put: user_id, role, expiry. Not: passwords, API keys.
text — a real JWT
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
.eyJzdWIiOiI0MiIsImV4cCI6MTcxNzAwMDAwMH0
.xK3nFm8jQwPxV2mRtLd9oYeN1sZqA7bCuHvDpEfGhI

Decoded header:  {"alg": "HS256", "typ": "JWT"}
Decoded payload: {"sub": "42", "exp": 1717000000}
                  ^^ user ID     ^^ expiry timestamp (Unix)

Paste any JWT at https://jwt.io to decode it — it's not encrypted.
JWTs are not encrypted — they are signed. Anyone who has the token can base64-decode and read the payload. Never put sensitive data (passwords, SSNs, API keys) in the payload. Only put identifiers (user_id, role) and the expiry time.

Install python-jose + Set SECRET_KEY

python-jose creates and verifies JWTs. The SECRET_KEY is used to sign every token — if it leaks, attackers can forge tokens for any user. Generate it once with Python's secrets module and store it in your .env.

bash + .env
pip install python-jose[cryptography]

# Generate a secure random key (run once, save the output):
python -c "import secrets; print(secrets.token_hex(32))"
# → a6f3e8c1d2b4...  (64 hex chars = 32 bytes = 256 bits)

# .env
SECRET_KEY=a6f3e8c1d2b4...your_generated_key_here
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=60

create_access_token()

The function takes a dict of data to embed in the token, adds an expiry timestamp, and signs it with the SECRET_KEY. Add this to auth.py alongside the password helpers.

python
from jose import jwt
from datetime import datetime, timedelta, timezone
import os
from dotenv import load_dotenv
load_dotenv()

SECRET_KEY = os.getenv("SECRET_KEY")
ALGORITHM  = os.getenv("ALGORITHM", "HS256")
ACCESS_TOKEN_EXPIRE_MINUTES = int(os.getenv("ACCESS_TOKEN_EXPIRE_MINUTES", 60))

def create_access_token(data: dict) -> str:
    """Create a signed JWT with an expiry time."""
    payload = data.copy()
    expire  = datetime.now(timezone.utc) + timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES)
    payload["exp"] = expire   # "exp" is a standard JWT claim — python-jose checks it on decode

    return jwt.encode(payload, SECRET_KEY, algorithm=ALGORITHM)
    # Returns a string like "eyJhbGci..."

# Usage:
# token = create_access_token({"sub": str(user.id)})
# "sub" (subject) is the standard claim for the user identifier

decode_token()

jwt.decode() verifies the signature and checks the expiry. If either fails, it raises a JWTError. You catch that and return None — the caller then raises a 401.

python
from jose import jwt, JWTError

def decode_token(token: str) -> dict | None:
    """Decode and verify a JWT. Returns the payload dict, or None if invalid/expired."""
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        # jwt.decode() automatically checks:
        #   - signature is valid (matches SECRET_KEY)
        #   - token has not expired (exp claim)
        return payload
    except JWTError:
        # Raised for: bad signature, expired token, malformed token
        return None

# payload["sub"] → the user ID we put in when creating the token

get_current_user() Dependency

This FastAPI dependency reads the Authorization: Bearer <token> header, decodes the token, and returns the User object from the database. Any route that declares it as a parameter gets the current user injected automatically — and gets a 401 if the token is missing or invalid.

python
from fastapi import Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer
from sqlalchemy.orm import Session
from database import get_db
import models

# OAuth2PasswordBearer tells FastAPI where to find the token in the request
# tokenUrl is the login endpoint — used by the /docs Authorize button
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/login")

def get_current_user(
    token: str    = Depends(oauth2_scheme),  # extracts Bearer token from header
    db:    Session = Depends(get_db),
) -> models.User:
    credentials_error = HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="Could not validate credentials",
        headers={"WWW-Authenticate": "Bearer"},
    )
    payload = decode_token(token)
    if not payload:
        raise credentials_error

    user_id: str = payload.get("sub")
    if not user_id:
        raise credentials_error

    user = db.query(models.User).filter(models.User.id == int(user_id)).first()
    if not user:
        raise credentials_error
    if not user.is_active:
        raise HTTPException(status_code=403, detail="Account suspended")

    return user

Protecting a Route

Add current_user: User = Depends(get_current_user) to any route parameter. FastAPI runs the dependency automatically — if the token is missing or invalid, the request is rejected with a 401 before your route function even runs.

python
from auth import get_current_user

# Anyone with a valid token can call this
@app.get("/me")
def get_me(current_user: models.User = Depends(get_current_user)):
    return {"id": current_user.id, "email": current_user.email}

# A route that uses the current user for something
@app.post("/notes")
def create_note(
    text:         str,
    current_user: models.User = Depends(get_current_user),
    db:           Session     = Depends(get_db),
):
    # current_user.id is the authenticated user — no need to pass user_id in the body
    note = models.Note(text=text, owner_id=current_user.id)
    db.add(note)
    db.commit()
    return {"text": note.text, "owner": current_user.email}

# No Depends → public, no auth required
@app.get("/public")
def public_route():
    return {"message": "Anyone can call this"}

Login Route Returns Token

Update the login route from the password guide to return a JWT token. The client stores this token and sends it in the Authorization header on every subsequent request.

python
from auth import hash_password, verify_password, create_access_token

@app.post("/login")
def login(email: str, password: str, db: Session = Depends(get_db)):
    user = db.query(models.User).filter(models.User.email == email).first()
    if not user or not verify_password(password, user.hashed_password):
        raise HTTPException(
            status_code=401,
            detail="Invalid email or password",
            headers={"WWW-Authenticate": "Bearer"},
        )
    if not user.is_active:
        raise HTTPException(status_code=403, detail="Account suspended")

    # Create a token with the user's ID as the subject
    token = create_access_token(data={"sub": str(user.id)})

    return {
        "access_token": token,
        "token_type":   "bearer",
    }

# Client usage:
# Authorization: Bearer eyJhbGci...

Testing with /docs

FastAPI's auto-generated docs at /docs has an Authorize button that stores the token for you, making it easy to test protected routes without writing a frontend.

text
1. Start the server: uvicorn main:app --reload
2. Open: http://localhost:8000/docs

3. Call POST /register to create a user:
   email=test@example.com, password=secret123

4. Call POST /login with the same credentials.
   Copy the "access_token" from the response.

5. Click the "Authorize" button (padlock icon, top right).
   Paste the token in the "Value" field.
   Click Authorize → Close.

6. Now call GET /me — you should get your user info back.
   The /docs UI automatically adds the Authorization header.

7. To test expiry: wait until the token expires (set
   ACCESS_TOKEN_EXPIRE_MINUTES=1 for a quick test),
   then call /me again — you should get a 401.

Token Expiry

When an access token expires, the server returns 401 Unauthorized. The client needs to get a new token. In the next guide, this is handled automatically with a refresh token — the client uses the refresh token to get a new access token without the user re-entering their password.

json — expired token response
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer

{
  "detail": "Could not validate credentials"
}

// The client should:
// 1. Detect the 401
// 2. Use the refresh token to get a new access token (auth-refresh.html)
// 3. Retry the original request with the new token
// 4. If refresh also fails → redirect to login
How long should tokens last? Short-lived (15–60 minutes) = more secure but requires frequent refresh. Long-lived (days/weeks) = less friction but a stolen token is valid longer. The standard pattern: short access token (15–60 min) + long refresh token (7–30 days). See Refresh Token Rotation.
