Public API Integration with FastAPI

Learn to call any external API — no auth, API key, or complex OAuth — using httpx. Three real examples: PokéAPI (free, no key), OpenWeatherMap (free API key), and NewsAPI (free API key + query params). Ends with a working no-JS dashboard page.

1

What is a Public API?

A public API is a URL that returns data as JSON. You make an HTTP GET request to it, it replies with structured data, and you use that data in your app. There is no database to set up on your end, no backend to write — the data lives on their servers. You just fetch it.

APIAuthWhat it returnsBase URL
PokéAPINone — completely freePokémon datapokeapi.co/api/v2
OpenWeatherMapAPI key (free tier)Current weatherapi.openweathermap.org
NewsAPIAPI key (free tier)News headlinesnewsapi.org/v2
GitHub APINone or tokenRepos, users, issuesapi.github.com
REST CountriesNone — completely freeCountry inforestcountries.com/v3.1
No auth vs API key: PokéAPI trusts everyone — no registration needed. OpenWeatherMap gives you 1,000 free calls per day if you create an account and get a key. The key just identifies you so they can enforce limits. It is not a security measure — never treat a public API key like a password, but still don't commit it to GitHub.

The Core Pattern

Every public API call follows the same three lines. Learn this pattern and you can call any API on the internet. Everything else — authentication, query params, parsing the response — is just variations on these three lines.

python
import httpx

# 1. Make the GET request to the URL
response = httpx.get("https://pokeapi.co/api/v2/pokemon/pikachu")

# 2. Parse the JSON response into a Python dict
data = response.json()

# 3. Use the data
print(data["name"])          # "pikachu"
print(data["base_experience"]) # 112
print(data["height"])         # 4  (in decimetres)

# That's it. 90% of all API integration work is these three lines.
python — run this now
# Save as test_api.py and run: python test_api.py
import httpx

response = httpx.get("https://pokeapi.co/api/v2/pokemon/bulbasaur")
data     = response.json()

print("Name:",    data["name"])
print("Weight:",  data["weight"], "hectograms")
print("Types:",   [t["type"]["name"] for t in data["types"]])
print("Abilities:",[a["ability"]["name"] for a in data["abilities"]])

# Expected output:
# Name:     bulbasaur
# Weight:   69 hectograms
# Types:    ['grass', 'poison']
# Abilities:['overgrow', 'chlorophyll']
Why httpx and not requests? Both work. httpx supports both sync and async, integrates cleanly with FastAPI, and is the modern choice. The API is almost identical to requests — if you already know requests, you already know httpx.

Example 1 — PokéAPI (No Auth)

PokéAPI is the perfect first API to practice with — completely free, no registration, rich data. Add a FastAPI route that fetches a Pokémon by name and returns the data you care about.

python
from fastapi import FastAPI, HTTPException
import httpx

app = FastAPI()

@app.get("/pokemon/{name}")
def get_pokemon(name: str):
    # name comes from the URL path: /pokemon/charizard
    url = f"https://pokeapi.co/api/v2/pokemon/{name.lower()}"

    response = httpx.get(url)

    if response.status_code == 404:
        raise HTTPException(status_code=404, detail=f"Pokémon '{name}' not found")

    response.raise_for_status()   # handle other errors (5xx etc.)
    data = response.json()

    # Return only the fields we care about — don't dump the whole 200-field response
    return {
        "name":    data["name"],
        "id":      data["id"],
        "height":  data["height"],
        "weight":  data["weight"],
        "types":   [t["type"]["name"] for t in data["types"]],
        "sprite":  data["sprites"]["front_default"],  # image URL
    }

# Test: http://localhost:8000/pokemon/pikachu

Key principle: Always pick out only the fields your app needs from the API response. Returning or storing the raw 200-field JSON object is slow, wastes memory, and makes debugging harder. Flatten it into a clean dict of just what you use.

Reading the Docs

Every API has documentation. Learning to read docs quickly is the real skill — not memorising any one API. Every doc page has the same four things you need.

text — how to read any API docs
1. BASE URL
   The root URL all endpoints share.
   PokéAPI example: https://pokeapi.co/api/v2
   Everything after this is the endpoint path.

2. ENDPOINT PATH
   Combined with the base URL to form the full request URL.
   Example endpoint:  /pokemon/{name}
   Full URL:          https://pokeapi.co/api/v2/pokemon/pikachu
   Path parameters like {name} go directly in the URL.

3. QUERY PARAMETERS
   Appended to the URL after a ? — used for filters, pagination, API keys.
   Example: /pokemon?limit=20&offset=40
   In Python: httpx.get(url, params={"limit": 20, "offset": 40})
   httpx automatically encodes the ? and & for you.

4. RESPONSE SHAPE
   The JSON structure the API returns.
   Look for: What key holds the data you want?
   PokéAPI:     data["name"], data["types"]
   OpenWeather: data["main"]["temp"], data["weather"][0]["description"]
   NewsAPI:     data["articles"][0]["title"]

PRACTICE: Open https://pokeapi.co/api/v2/pokemon/ditto in your browser.
Read the raw JSON. Find: the "types" array, the "abilities" list,
and the "sprites.front_default" image URL.

Example 2 — OpenWeatherMap (API Key)

OpenWeatherMap gives 1,000 free calls per day. You pass your API key as a query parameter — it's not a secret in the same way a password is, but you still load it from .env so it's not hardcoded in your source code.

python
import os
from dotenv import load_dotenv
load_dotenv()

WEATHER_KEY = os.getenv("OPENWEATHER_API_KEY")

@app.get("/weather/{city}")
def get_weather(city: str, units: str = "metric"):
    # units: "metric" = Celsius, "imperial" = Fahrenheit, "standard" = Kelvin
    response = httpx.get(
        "https://api.openweathermap.org/data/2.5/weather",
        params={
            "q":     city,
            "appid": WEATHER_KEY,   # API key goes here as a query param
            "units": units,
        }
    )

    if response.status_code == 404:
        raise HTTPException(status_code=404, detail=f"City '{city}' not found")
    if response.status_code == 401:
        raise HTTPException(status_code=500, detail="Invalid API key")

    response.raise_for_status()
    data = response.json()

    return {
        "city":        data["name"],
        "country":     data["sys"]["country"],
        "temp":        data["main"]["temp"],
        "feels_like":  data["main"]["feels_like"],
        "humidity":    data["main"]["humidity"],
        "description": data["weather"][0]["description"],
        "icon":        f"https://openweathermap.org/img/wn/{data['weather'][0]['icon']}@2x.png",
    }

# Test: http://localhost:8000/weather/London
# With units: http://localhost:8000/weather/London?units=imperial

Handling Errors

APIs can fail in several ways. A proper error handler means your app returns a clear message to the user instead of crashing with an unhandled Python exception.

text — HTTP status codes you'll see
200 OK              — Request succeeded. Response body has your data.

400 Bad Request     — You sent something malformed (wrong field name, bad format).
                      Check your params dict.

401 Unauthorized    — Missing or invalid API key / token.
                      Check your .env and that you're passing the key correctly.

403 Forbidden       — Valid key, but you don't have permission for this resource.
                      Check your plan/scopes.

404 Not Found       — The resource doesn't exist (e.g. city name typo, unknown Pokémon).
                      Show the user a friendly "not found" message.

422 Unprocessable   — Valid request format, but values are wrong.
                      Common with FastAPI when query params fail validation.

429 Too Many Reqs   — Rate limit hit. Wait before retrying.
                      Free tiers usually reset hourly or daily.

500 Server Error    — Their API crashed. Nothing you can do. Try again later.
python — reusable error handler
def safe_get(url: str, params: dict = None) -> dict:
    """Make a GET request and return JSON, or raise HTTPException on failure."""
    try:
        response = httpx.get(url, params=params, timeout=10)
    except httpx.TimeoutException:
        raise HTTPException(status_code=504, detail="API timed out")
    except httpx.RequestError:
        raise HTTPException(status_code=503, detail="Could not reach API")

    if response.status_code == 404:
        raise HTTPException(status_code=404, detail="Not found")
    if response.status_code == 401:
        raise HTTPException(status_code=500, detail="Invalid API key")
    if response.status_code == 429:
        raise HTTPException(status_code=429, detail="Rate limit hit — try again later")

    response.raise_for_status()   # catch anything else (5xx etc.)
    return response.json()

# Use it instead of httpx.get() directly:
# data = safe_get("https://pokeapi.co/api/v2/pokemon/missingno")

Caching Responses

If your FastAPI route calls an external API on every request, you'll quickly hit rate limits and slow down your app. A simple in-memory cache stores the last response with a timestamp. If the cache is fresh, return it immediately without hitting the API again.

python — in-memory cache
import time

# A dict that stores: key → {"data": ..., "expires": timestamp}
_cache: dict = {}

def cache_get(key: str):
    """Return cached data if it exists and hasn't expired. Else None."""
    entry = _cache.get(key)
    if entry and time.time() < entry["expires"]:
        return entry["data"]
    return None

def cache_set(key: str, data, ttl_seconds: int = 300):
    """Store data in cache for ttl_seconds (default 5 minutes)."""
    _cache[key] = {
        "data":    data,
        "expires": time.time() + ttl_seconds,
    }

# TTL = "Time To Live" — how long the cached data stays valid
# Weather: 5 mins is fine (it doesn't change second-to-second)
# News: 15-30 mins is fine
# Pokémon: 24 hours is fine (the data never changes)
python — weather with cache
@app.get("/weather/{city}")
def get_weather(city: str, units: str = "metric"):
    cache_key = f"weather:{city}:{units}"  # unique key per city + unit combo

    # Check cache first
    cached = cache_get(cache_key)
    if cached:
        return {**cached, "from_cache": True}   # return cached result immediately

    # Cache miss — call the real API
    data = safe_get(
        "https://api.openweathermap.org/data/2.5/weather",
        params={"q": city, "appid": WEATHER_KEY, "units": units}
    )
    result = {
        "city":        data["name"],
        "temp":        data["main"]["temp"],
        "description": data["weather"][0]["description"],
        "icon":        f"https://openweathermap.org/img/wn/{data['weather'][0]['icon']}@2x.png",
    }
    cache_set(cache_key, result, ttl_seconds=300)   # cache for 5 mins
    return {**result, "from_cache": False}
In-memory only: This cache lives in RAM and disappears when you restart the server. For a production app with multiple workers, use Redis instead. But for a single-worker learning project or side project, this is perfectly fine.

Example 3 — NewsAPI (API Key + Query Params)

NewsAPI searches live headlines by topic. It introduces multiple query parameters — q for the search term, language, pageSize — and a response that's a list inside a articles key.

python
NEWS_KEY = os.getenv("NEWS_API_KEY")

@app.get("/news")
def get_news(
    topic:    str = "technology",   # query param: /news?topic=sports
    count:    int = 5,              # how many articles to return
    language: str = "en",
):
    cache_key = f"news:{topic}:{language}"
    cached = cache_get(cache_key)
    if cached:
        return cached[:count]   # slice cached list to requested count

    data = safe_get(
        "https://newsapi.org/v2/everything",
        params={
            "q":        topic,
            "language": language,
            "pageSize": 20,         # fetch 20, cache them, return slice
            "sortBy":   "publishedAt",
            "apiKey":   NEWS_KEY,     # NewsAPI uses apiKey, not appid
        }
    )

    # Flatten the articles list
    articles = [
        {
            "title":       a["title"],
            "source":      a["source"]["name"],
            "url":         a["url"],
            "published_at": a["publishedAt"],
            "description": a["description"] or "",
        }
        for a in data["articles"]
        if a["title"] != "[Removed]"   # NewsAPI sometimes returns deleted articles
    ]

    cache_set(cache_key, articles, ttl_seconds=900)   # cache 15 mins
    return articles[:count]

# Test: http://localhost:8000/news?topic=AI&count=3

Building a Mini Dashboard

Wire all three APIs into a single-page Jinja2 dashboard — a Pokémon lookup by name, a weather card for any city, and a news feed by topic. Three forms, three FastAPI routes, one template. No JavaScript.

python
from fastapi.templating import Jinja2Templates
from fastapi.responses import HTMLResponse
from fastapi.staticfiles import StaticFiles

templates = Jinja2Templates(directory="templates")
app.mount("/static", StaticFiles(directory="static"), name="static")

@app.get("/dashboard", response_class=HTMLResponse)
def dashboard(
    request: Request,
    pokemon: str = "",   # query param from search form
    city:    str = "",
    topic:   str = "technology",
):
    pokemon_data = None
    weather_data = None
    news_data    = []
    errors       = {}

    if pokemon:
        try:
            pokemon_data = get_pokemon(pokemon)   # reuse the route function
        except HTTPException as e:
            errors["pokemon"] = e.detail

    if city:
        try:
            weather_data = get_weather(city)
        except HTTPException as e:
            errors["weather"] = e.detail

    news_data = get_news(topic=topic, count=5)

    return templates.TemplateResponse("dashboard.html", {
        "request":      request,
        "pokemon":      pokemon_data,
        "weather":      weather_data,
        "news":         news_data,
        "errors":       errors,
        "search_vals":  {"pokemon": pokemon, "city": city, "topic": topic},
    })
html + jinja2 — dashboard template
<!DOCTYPE html>
<html><head>
  <title>API Dashboard</title>
  <link rel="stylesheet" href="/static/style.css">
</head><body>

<header><h1>API Dashboard</h1></header>

<main>

  <!-- Search forms use GET so results are bookmarkable -->
  <div class="search-row">
    <form method="get" action="/dashboard">
      <input name="pokemon" placeholder="Pokémon name..."
             value="{{ search_vals.pokemon }}">
      <button>Search</button>
    </form>
    <form method="get" action="/dashboard">
      <input name="city" placeholder="City name..."
             value="{{ search_vals.city }}">
      <button>Weather</button>
    </form>
  </div>

  <!-- Pokémon result -->
  {% if errors.pokemon %}
    <p class="error">{{ errors.pokemon }}</p>
  {% elif pokemon %}
    <div class="card">
      <img src="{{ pokemon.sprite }}" alt="{{ pokemon.name }}">
      <h2>{{ pokemon.name | title }}</h2>
      <p>Types: {{ pokemon.types | join(", ") }}</p>
    </div>
  {% endif %}

  <!-- Weather result -->
  {% if weather %}
    <div class="card">
      <img src="{{ weather.icon }}" alt="weather icon">
      <h2>{{ weather.city }}, {{ weather.country }}</h2>
      <p>{{ weather.temp }}°C — {{ weather.description }}</p>
    </div>
  {% endif %}

  <!-- News feed -->
  <section><h2>Latest: {{ search_vals.topic | title }}</h2>
    {% for article in news %}
      <div class="news-item">
        <a href="{{ article.url }}" target="_blank">{{ article.title }}</a>
        <span class="source">{{ article.source }}</span>
      </div>
    {% endfor %}
  </section>

</main>
</body></html>
GET forms for search: The search forms use method="get" instead of POST because search queries belong in the URL. /dashboard?city=London is bookmarkable and shareable. Use GET for any form that only reads data.

What's Next

You've learned the universal pattern for calling any external API from FastAPI. Everything in the CRM guide, the AI chat guide, and real freelance projects uses these same three lines: httpx.get() → .json() → use the data.

Async routes: Replace httpx.get() with await httpx.AsyncClient().get() and mark your route with async def. This lets FastAPI handle other requests while waiting for the API to respond — important when you have many users.
Retry on 429: Add automatic backoff when the API rate limits you. The tenacity library makes this one decorator: @retry(wait=wait_exponential(min=1, max=10), stop=stop_after_attempt(3)).
More free APIs to try: REST Countries (restcountries.com — no key), Open Meteo (open-meteo.com — free weather, no key), GitHub API (api.github.com — public repos need no key), NASA APOD (api.nasa.gov — free key, one image per day).
From proxy to value-add: Your FastAPI routes are currently just passing through data from other APIs. The real value comes when you combine them — use NewsAPI to get headlines, then pass them to the Claude API (AI Chat guide) to generate a daily briefing, then cache it for all users.
