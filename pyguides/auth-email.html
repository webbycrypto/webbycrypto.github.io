Email Verification

Require users to confirm they own the email address they registered with before they can log in. Covers the full flow: token generation, sending the link, the verify endpoint, blocking unverified logins, and resend.

1

Why Email Verification?

Without verification, anyone can register with ceo@bigcorp.com and your app has no way to know the person doesn't own that address. Email verification confirms the registrant can receive mail at that address — they clicked a link that only arrived in their inbox.

Three benefits: (1) Prevents spam/bot accounts using fake addresses. (2) Ensures you can actually contact the user for password resets. (3) Reduces abuse from throwaway signups. Most SaaS products require it before the account can do anything meaningful.
2

The Full Flow

text
1. POST /register
   → Create user with email_verified=False
   → Generate a random verification token
   → Store token (hashed) in DB with 24hr expiry
   → Send email with link: GET /auth/verify?token=RAW_TOKEN

2. User clicks the link in their email

3. GET /auth/verify?token=RAW_TOKEN
   → Find matching token in DB (bcrypt verify)
   → Check it hasn't expired
   → Set user.email_verified = True
   → Delete the token row
   → Redirect to /login (or return success JSON)

4. POST /login
   → After password check: if not user.email_verified → 403
   → Only verified users get a token

5. POST /auth/resend-verification
   → Delete any existing token for this user
   → Generate a new one
   → Resend the email
3

email_verified Column

Add one column to the User model. This is the only change to the existing model — the verification logic lives in a separate table.

python
class User(Base):
    __tablename__ = "users"
    id              = Column(Integer, primary_key=True, index=True)
    email           = Column(String, unique=True, nullable=False, index=True)
    hashed_password = Column(String, nullable=False)
    is_active       = Column(Boolean, default=True)
    email_verified  = Column(Boolean, default=False)   # ← new column
    created_at      = Column(DateTime, default=lambda: datetime.now(timezone.utc))
If using PostgreSQL in production: adding a column requires an Alembic migration — create_all() won't add it to an existing table. Run: alembic revision --autogenerate -m "add email_verified" then alembic upgrade head.

Verification Token Table

Store the verification token in the database with an expiry. Hash it like a password — if the table is leaked, tokens can't be used.

python
import secrets

class VerificationToken(Base):
    __tablename__ = "verification_tokens"
    id         = Column(Integer, primary_key=True)
    user_id    = Column(Integer, ForeignKey("users.id"), nullable=False)
    token_hash = Column(String, unique=True, nullable=False)
    expires_at = Column(DateTime, nullable=False)

def make_verification_token(user_id: int, db: Session):
    """Generate a token, store its hash, return the raw token (to send in the link)."""
    # Delete any existing token for this user first
    db.query(VerificationToken).filter(
        VerificationToken.user_id == user_id
    ).delete()

    raw   = secrets.token_urlsafe(32)   # 32 bytes → ~43 URL-safe chars
    hashed = pwd_context.hash(raw)
    expires = datetime.now(timezone.utc) + timedelta(hours=24)
    db.add(VerificationToken(user_id=user_id, token_hash=hashed, expires_at=expires))
    db.commit()
    return raw   # put this in the email link

Send the Email

Two options: smtplib (built into Python, works with Gmail/SMTP) or a transactional email API like Resend. Resend is simpler for production — one pip install and an API key.

python — Resend
# pip install resend
# Get free API key at resend.com (100 emails/day free)
import resend
resend.api_key = os.getenv("RESEND_API_KEY")

def send_verification_email(to_email: str, raw_token: str):
    base_url = os.getenv("APP_BASE_URL", "http://localhost:8000")
    link = f"{base_url}/auth/verify?token={raw_token}"
    resend.Emails.send({
        "from":    "noreply@yourapp.com",
        "to":      [to_email],
        "subject": "Verify your email",
        "html":    f"<p>Click to verify: <a href='{link}'>{link}</a></p><p>Expires in 24 hours.</p>",
    })
python — smtplib (Gmail)
import smtplib
from email.mime.text import MIMEText

def send_verification_email(to_email: str, raw_token: str):
    base_url = os.getenv("APP_BASE_URL", "http://localhost:8000")
    link = f"{base_url}/auth/verify?token={raw_token}"

    msg = MIMEText(f"Click to verify your email:\n{link}\n\nExpires in 24 hours.")
    msg["Subject"] = "Verify your email"
    msg["From"]    = os.getenv("SMTP_FROM")
    msg["To"]      = to_email

    with smtplib.SMTP_SSL("smtp.gmail.com", 465) as smtp:
        smtp.login(os.getenv("SMTP_USER"), os.getenv("SMTP_PASSWORD"))
        smtp.send_message(msg)
# Gmail: use an "App Password" (not your account password)
# Google Account → Security → 2-Step Verification → App passwords

GET /auth/verify

The user clicks the link in their email. This endpoint finds the matching token, marks the user as verified, and deletes the token so it can't be used again.

python
@app.get("/auth/verify")
def verify_email(token: str, db: Session = Depends(get_db)):
    now = datetime.now(timezone.utc)

    # Find non-expired verification tokens
    candidates = db.query(models.VerificationToken).filter(
        models.VerificationToken.expires_at > now
    ).all()

    token_row = None
    for row in candidates:
        if pwd_context.verify(token, row.token_hash):
            token_row = row
            break

    if not token_row:
        raise HTTPException(status_code=400, detail="Invalid or expired verification link")

    # Mark the user as verified
    user = db.query(models.User).filter(models.User.id == token_row.user_id).first()
    user.email_verified = True

    # Delete the token — single use
    db.delete(token_row)
    db.commit()

    return {"message": "Email verified. You can now log in."}
    # Or: return RedirectResponse("/login", status_code=303) for HTML apps

Block Unverified Logins

One extra check in the login route — after the password is verified, before issuing the token.

python
@app.post("/login")
def login(email: str, password: str, db: Session = Depends(get_db)):
    user = db.query(models.User).filter(models.User.email == email).first()
    if not user or not verify_password(password, user.hashed_password):
        raise HTTPException(status_code=401, detail="Invalid email or password")
    if not user.is_active:
        raise HTTPException(status_code=403, detail="Account suspended")

    # ← New check: block unverified accounts
    if not user.email_verified:
        raise HTTPException(
            status_code=403,
            detail="Email not verified. Check your inbox for the verification link."
        )

    token = create_access_token(data={"sub": str(user.id)})
    return {"access_token": token, "token_type": "bearer"}

Resend Verification

Users sometimes miss the email or let it expire. Provide an endpoint to generate a new token and resend — but rate-limit it or require a recent login to prevent abuse.

python
@app.post("/auth/resend-verification")
def resend_verification(email: str, db: Session = Depends(get_db)):
    user = db.query(models.User).filter(models.User.email == email).first()

    # Don't reveal if the email exists — return the same message either way
    if not user or user.email_verified:
        return {"message": "If that email is registered and unverified, a new link has been sent."}

    raw_token = make_verification_token(user.id, db)  # deletes old, creates new
    send_verification_email(user.email, raw_token)
    return {"message": "If that email is registered and unverified, a new link has been sent."}

# Note: in production, add rate limiting to this endpoint
# (e.g. max 3 resends per hour per email) to prevent email bombing
