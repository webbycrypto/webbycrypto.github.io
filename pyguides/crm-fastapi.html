CRM Integration with FastAPI

Learn the universal patterns behind CRM APIs — reading and writing contacts, OAuth2 vs API keys, webhook handling, deduplication, and Unified.to. Uses HubSpot as the primary example with notes showing how every concept maps to Salesforce, Zoho, and Pipedrive.

1

What CRMs Expose

Every CRM, regardless of brand, stores roughly the same objects: Contacts (people), Companies (organisations), Deals or Opportunities (sales pipeline), and Activities (calls, emails, notes). The field names differ, but the data model is nearly identical across HubSpot, Salesforce, Zoho, and Pipedrive. Learn the pattern once and it transfers everywhere.

ConceptHubSpotSalesforceZohoPipedrive
A personContactContact / LeadContact / LeadPerson
A companyCompanyAccountAccountOrganization
A sales opportunityDealOpportunityDealDeal
An email/call logEngagement / ActivityActivity / TaskActivityActivity
REST pattern: Almost all CRM APIs follow REST. The URL pattern is /objects/{type} for a list and /objects/{type}/{id} for one record. HubSpot example: GET /crm/v3/objects/contacts returns a paginated list; GET /crm/v3/objects/contacts/123 returns contact 123.

Auth: API Key vs OAuth2

CRMs use two main auth methods. Start with the simpler one for your first integration — you can add OAuth2 later once you understand the data flow.

python — API key
# HubSpot Private App token — easiest way to get started
# Also used by: Pipedrive (API token), Zoho (self-client token)

import httpx, os
from dotenv import load_dotenv
load_dotenv()

HUBSPOT_TOKEN = os.getenv("HUBSPOT_TOKEN")

def hs_headers():
    return {
        "Authorization": f"Bearer {HUBSPOT_TOKEN}",
        "Content-Type": "application/json",
    }

# Every API call passes these headers. That's it.
python — OAuth2 flow overview
# OAuth2 is required for Salesforce and multi-tenant HubSpot apps
# The three steps:

# 1. Redirect the user to the CRM's authorization URL
auth_url = (
    "https://app.hubspot.com/oauth/authorize"
    "?client_id=YOUR_CLIENT_ID"
    "&redirect_uri=https://yourapp.com/oauth/callback"
    "&scope=crm.objects.contacts.read"
)

# 2. CRM redirects back to your callback URL with a code
@app.get("/oauth/callback")
def oauth_callback(code: str):
    # Exchange the code for an access token + refresh token
    token_resp = httpx.post(
        "https://api.hubapi.com/oauth/v1/token",
        data={
            "grant_type": "authorization_code",
            "client_id": os.getenv("CLIENT_ID"),
            "client_secret": os.getenv("CLIENT_SECRET"),
            "redirect_uri": "https://yourapp.com/oauth/callback",
            "code": code,
        }
    )
    tokens = token_resp.json()
    access_token  = tokens["access_token"]
    refresh_token = tokens["refresh_token"]
    # TODO: save both tokens to your database

# 3. Use access_token for API calls; use refresh_token to get a new
#    access_token when it expires (usually after 30 minutes)
Salesforce: Always requires OAuth2. Uses https://login.salesforce.com/services/oauth2/authorize. Access tokens expire after a few hours; the refresh token is long-lived. Zoho: Offers both a "self-client" token (like an API key, good for your own account) and full OAuth2 for multi-user apps.

HubSpot's free developer account gives you a sandbox CRM with sample data. It takes about 3 minutes to set up and you'll have a real API token in your hands.

text — one-time setup

   - crm.objects.contacts.write

Your First CRM Read

Reading contacts is the most common first operation. HubSpot's v3 API returns paginated results in a results array. Each contact has a properties object with the actual field values.

python
def list_contacts(limit: int = 10, after: str = None) -> dict:
    """Fetch a page of contacts. 'after' is the pagination cursor."""
    params = {
        "limit": limit,
        "properties": "firstname,lastname,email,phone",  # fields to include
    }
    if after:
        params["after"] = after   # pass cursor for page 2, 3, etc.

    resp = httpx.get(
        f"{BASE_URL}/crm/v3/objects/contacts",
        headers=_headers(),
        params=params,
    )
    resp.raise_for_status()
    data = resp.json()

    # Flatten each contact to a clean dict
    contacts = [
        {
            "id":        c["id"],
            "first_name": c["properties"].get("firstname", ""),
            "last_name":  c["properties"].get("lastname", ""),
            "email":      c["properties"].get("email", ""),
        }
        for c in data["results"]
    ]
    next_cursor = data.get("paging", {}).get("next", {}).get("after")
    return {"contacts": contacts, "next_cursor": next_cursor}
json — HubSpot response shape
{
  "results": [
    {

      "properties": {

        "phone":        "+1 555 0100",
        "createdate":   "2024-01-15T10:30:00.000Z",
        "hs_object_id": "101"
      },

}
Salesforce equivalent: GET /services/data/v58.0/query?q=SELECT+Id,FirstName,LastName,Email+FROM+Contact+LIMIT+10 — Salesforce uses SOQL (a SQL-like query language) instead of filter params. The concept is identical: paginated list of records with a cursor (called nextRecordsUrl).

Wrapping It in FastAPI

Your FastAPI routes are thin — they call crm_client.py functions and return the results. This keeps business logic out of routes and makes the CRM client easy to swap later.

python
from fastapi import FastAPI, HTTPException, Query
import crm_client

app = FastAPI()

@app.get("/contacts")
def get_contacts(
    limit: int = Query(10, ge=1, le=100),   # query param with validation
    after: str = Query(None),                 # pagination cursor, optional
):
    try:
        return crm_client.list_contacts(limit=limit, after=after)
    except httpx.HTTPStatusError as e:
        raise HTTPException(status_code=e.response.status_code,
                            detail="CRM API error")

# Test it: http://localhost:8000/contacts
# Next page:  http://localhost:8000/contacts?after=NTI1Cg%3D%3D
Why catch HTTPStatusError? If the CRM API returns a 401 or 429, raise_for_status() throws this error. Catching it lets you return a clean FastAPI response instead of an unhandled 500 crash.

Creating a Contact

Before creating a contact, always check if one already exists with that email — otherwise every re-run of your sync script creates duplicates. This deduplication pattern is the same across every CRM integration you'll ever build.

python
def find_contact_by_email(email: str) -> str | None:
    """Return the HubSpot contact ID if found, else None."""
    resp = httpx.post(
        f"{BASE_URL}/crm/v3/objects/contacts/search",
        headers=_headers(),
        json={
            "filterGroups": [{
                "filters": [{
                    "propertyName": "email",
                    "operator": "EQ",
                    "value": email
                }]
            }]
        }
    )
    resp.raise_for_status()
    results = resp.json()["results"]
    return results[0]["id"] if results else None


def create_contact(first: str, last: str, email: str, phone: str = "") -> dict:
    """Create or return existing contact — never creates duplicates."""
    existing_id = find_contact_by_email(email)
    if existing_id:
        return {"id": existing_id, "created": False}   # already exists

    resp = httpx.post(
        f"{BASE_URL}/crm/v3/objects/contacts",
        headers=_headers(),
        json={
            "properties": {
                "firstname": first,
                "lastname":  last,
                "email":     email,
                "phone":     phone,
            }
        }
    )
    resp.raise_for_status()
    return {"id": resp.json()["id"], "created": True}
python
@app.post("/contacts")
def post_contact(
    first: str,
    last:  str,
    email: str,
    phone: str = "",
):
    result = crm_client.create_contact(first, last, email, phone)
    if result["created"]:
        return {"status": "created", "id": result["id"]}
    return {"status": "already_exists", "id": result["id"]}
Salesforce equivalent: Use SOQL SELECT Id FROM Contact WHERE Email = 'x@y.com' before creating. Salesforce also has an upsert API that does both steps in one call using an external ID field.

Updating a Contact

Updates use PATCH — you only send the fields you want to change, not the entire record. This is standard across all modern CRM APIs.

python
def update_contact(contact_id: str, fields: dict) -> dict:
    """Update specific fields on a contact by HubSpot ID.

    Example:
        update_contact("101", {"phone": "+1 555 9999", "jobtitle": "CEO"})
    """
    resp = httpx.patch(
        f"{BASE_URL}/crm/v3/objects/contacts/{contact_id}",
        headers=_headers(),
        json={"properties": fields},   # only the fields to change
    )
    resp.raise_for_status()
    return resp.json()

# ─── HubSpot vs Salesforce field names ──────────────────────────────
#
# Concept          HubSpot property     Salesforce field
# ──────────────   ─────────────────    ────────────────
# First name       firstname            FirstName
# Last name        lastname             LastName
# Email            email                Email
# Phone            phone                Phone
# Job title        jobtitle             Title
# Company name     company              Account.Name (related object)
#
# Always check the CRM's property/field list — custom fields vary per account
PATCH vs PUT: PATCH updates only the fields you send. PUT replaces the entire record (any field you don't send gets wiped). Always use PATCH for CRM updates unless the docs specifically say otherwise.

Webhooks: CRM Pushes to You

Instead of polling the CRM every few minutes, you register a webhook URL and the CRM calls you whenever something changes. Your endpoint must return 200 OK quickly — process the work in the background so the CRM doesn't time out and retry.

python
from fastapi import BackgroundTasks, Request

@app.post("/webhooks/hubspot")
async def hubspot_webhook(
    request:    Request,
    background: BackgroundTasks,
):
    body = await request.body()

    # Verify the webhook came from HubSpot (see tab 2)
    signature = request.headers.get("X-HubSpot-Signature-v3", "")
    if not verify_hubspot_signature(body, signature):
        raise HTTPException(status_code=401, detail="Bad signature")

    events = await request.json()

    # Respond immediately — process in background
    background.add_task(process_webhook_events, events)
    return {"status": "ok"}


def process_webhook_events(events: list):
    for event in events:
        event_type = event.get("subscriptionType")
        object_id  = event.get("objectId")
        if event_type == "contact.creation":
            print(f"New contact: {object_id}")
            # TODO: sync to your local database
        elif event_type == "contact.propertyChange":
            print(f"Contact updated: {object_id}")
python — HMAC signature check
import hmac, hashlib, base64

CLIENT_SECRET = os.getenv("HUBSPOT_CLIENT_SECRET")

def verify_hubspot_signature(body: bytes, signature: str) -> bool:
    """Check that the webhook was signed by HubSpot with your client secret."""
    if not CLIENT_SECRET or not signature:
        return False
    expected = base64.b64encode(
        hmac.new(
            CLIENT_SECRET.encode(),
            body,
            hashlib.sha256
        ).digest()
    ).decode()
    return hmac.compare_digest(expected, signature)
# hmac.compare_digest() prevents timing attacks —
# always use it instead of == for security comparisons
Salesforce equivalent: Called "Outbound Messages" (SOAP) or "Platform Events". Salesforce also supports REST webhooks via Flow. The same BackgroundTasks pattern applies — always return 200 fast.

Unified.to: One SDK for All CRMs

Unified.to is a middleware layer that normalises CRM APIs. You write code once against the Unified.to SDK and it works with HubSpot, Salesforce, Zoho, Pipedrive, and 30+ others. Worth it when you need to support multiple CRMs without maintaining separate clients for each.

python
# pip install unified-python-sdk
import unified_to
from unified_to.models import shared

# Connect — use the connection_id from the Unified.to dashboard
sdk = unified_to.UnifiedTo(
    security=shared.Security(jwt=os.getenv("UNIFIED_API_KEY"))
)

# List contacts — same code works for ANY connected CRM
response = sdk.crm.list_crm_contacts(
    unified_to.models.operations.ListCrmContactsRequest(
        connection_id=os.getenv("CRM_CONNECTION_ID")  # which CRM account
    )
)

for contact in response.crm_contacts:
    print(contact.name, contact.emails)

# Create a contact — same code, different CRM
sdk.crm.create_crm_contact(
    unified_to.models.operations.CreateCrmContactRequest(
        connection_id=os.getenv("CRM_CONNECTION_ID"),
        crm_contact=shared.CrmContact(
            name="Jane Smith",
            emails=[shared.CrmEmail(email="jane@example.com")],
        )
    )
)

Syncing to Your Local Database

When you pull contacts from a CRM into your own database, you need a way to match records on future syncs without creating duplicates. Store the CRM's ID alongside your local record and use it as the uniqueness key on every upsert.

python — SQLite upsert
import sqlite3

# Create table with crm_id as the uniqueness key
def init_db():
    conn = sqlite3.connect("local.db")
    conn.execute("""
        CREATE TABLE IF NOT EXISTS contacts (
            id      INTEGER PRIMARY KEY AUTOINCREMENT,
            crm_id  TEXT UNIQUE,    -- HubSpot/Salesforce record ID
            name    TEXT,
            email   TEXT,
            synced_at TEXT
        )
    """)
    conn.commit()
    conn.close()

def upsert_contact(crm_id: str, name: str, email: str):
    """Insert or update — never creates duplicates."""
    conn = sqlite3.connect("local.db")
    conn.execute("""
        INSERT INTO contacts (crm_id, name, email, synced_at)
        VALUES (?, ?, ?, datetime('now'))
        ON CONFLICT(crm_id) DO UPDATE SET
            name      = excluded.name,
            email     = excluded.email,
            synced_at = excluded.synced_at
    """, (crm_id, name, email))
    conn.commit()
    conn.close()

# ON CONFLICT(crm_id) → if crm_id already exists, update instead of insert
# This is called an "upsert" — update-or-insert
python — bulk sync endpoint
@app.post("/sync/contacts")
def bulk_sync_contacts():
    """Pull ALL contacts from HubSpot and upsert into local DB."""
    synced = 0
    cursor = None

    while True:
        result = crm_client.list_contacts(limit=100, after=cursor)
        for c in result["contacts"]:
            upsert_contact(
                crm_id=c["id"],
                name=f"{c['first_name']} {c['last_name']}".strip(),
                email=c["email"],
            )
            synced += 1

        cursor = result["next_cursor"]
        if not cursor:
            break   # no more pages

    return {"synced": synced}

What's Next

You now understand the core patterns that power every CRM integration: auth, CRUD, webhooks, deduplication, and upsert syncing. These four things repeat in every integration job you'll see.

Pagination: The bulk sync above handles it with a while True / break loop. For very large CRMs (100k+ contacts), run this in a background task via BackgroundTasks so the HTTP request doesn't time out.
Rate limiting: HubSpot allows 110 requests per 10 seconds on the free plan. Salesforce has per-org daily limits. Add a simple counter and time.sleep() between batches, or use the httpx retry logic with exponential backoff.
Scheduling: Run the sync on a schedule with a cron job calling POST /sync/contacts. On a VPS: */30 * * * * curl -s -X POST http://localhost:8000/sync/contacts. See the Public API guide for caching patterns that reduce API calls between syncs.
Companies and Deals: The same patterns — list_*, create_*, update_*, upsert — apply to /crm/v3/objects/companies and /crm/v3/objects/deals. Try adding a list_deals() function to crm_client.py as practice.
