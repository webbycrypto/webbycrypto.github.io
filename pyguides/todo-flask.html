Todo App - Flask

Build a simple todo app with Flask, SQLite via Flask-SQLAlchemy, Jinja2 templates, and full CRUD - add, complete, and delete tasks.

1

Before You Start

Three concepts will make everything in this guide click before you write a single line of code. First - virtual environments: a venv is an isolated Python installation for your project, keeping its packages separate from every other project on your machine. You must activate it each time you open a new terminal; you will know it is active when you see (venv) in your prompt. Second - HTTP: every time a browser visits a URL it sends a request, and the server sends back a response. A GET request asks for data (loading a page); a POST request sends data (submitting a form). Flask routes are matched by both URL and method, which is why @app.route('/add', methods=['POST']) only responds to form submissions and ignores everything else. Third - SQLite: it is a database that lives in a single file called todos.db on your computer - no server, no installation, no configuration. It is ideal for learning and small apps; swapping it for PostgreSQL later is a one-line change.

bash 
# Create a virtual environment in your project folder
python -m venv venv

# Activate it - run this every time you open a new terminal
venv\Scripts\activate        # Windows
source venv/bin/activate      # macOS / Linux

# Your prompt will show (venv) when it is active.
# Now install dependencies:
pip install flask flask-sqlalchemy python-dotenv

# Or install offline if you have already downloaded the bundle:
pyoffline install --bundle flask

Project Structure

Flask gives you full control over how you organise your project - there is no required layout enforced by the framework. For a small app, putting everything in a single app.py keeps it easy to read without jumping between files. Flask works by mapping URL paths (like / or /add) to Python functions called view functions; when a request arrives, Flask checks its route table and calls the matching function. Templates live in a templates/ folder by convention - Flask finds them there automatically when you call render_template(), so you never have to specify the full path. The .env file keeps secrets like your SECRET_KEY out of your source code so they are never accidentally committed to version control.

text 
todo-flask/
  app.py            ← app factory, db, routes all in one file (simple app)
  templates/
    base.html       ← shared page shell (nav, flash messages)
    index.html      ← todo list + add form
  .env              ← SECRET_KEY
  requirements.txt

App Setup & Todo Model

Putting app setup, model, and routes all in one file is a valid and common choice for small Flask apps - Flask does not enforce any particular project structure on you. Flask-SQLAlchemy is a thin wrapper around SQLAlchemy that ties the database connection to your Flask app object, so you never have to open or close connections manually - the library handles that. The shared db object is used throughout the file for both defining models and running queries. The app.app_context() block is necessary because Flask-SQLAlchemy needs to know which app it belongs to before it can do anything; db.create_all() reads every db.Model subclass and creates the matching table if it does not already exist. The nullable=False constraint on title tells the database to reject any row saved without a title - this is enforced at the database level, not just in Python, so it cannot be bypassed by going around your code.

python 
from flask import Flask, render_template, request, redirect, url_for, flash
from flask_sqlalchemy import SQLAlchemy
from datetime import datetime
import os

app = Flask(__name__)
# SECRET_KEY is used by Flask to sign session cookies (required for flash messages).
# In production, set this to a long random string via an environment variable.
app.config["SECRET_KEY"]                = os.getenv("SECRET_KEY", "dev-secret")
app.config["SQLALCHEMY_DATABASE_URI"]   = "sqlite:///todos.db"
# Disabling TRACK_MODIFICATIONS turns off an optional Flask-SQLAlchemy feature
# that emits signals on every model change - it's not needed here and saves memory.
app.config["SQLALCHEMY_TRACK_MODIFICATIONS"] = False

db = SQLAlchemy(app)  # db is shared across the whole file - models and routes both use it

# ── Model ──────────────────────────────────────────────────────────────────

class Todo(db.Model):
    id         = db.Column(db.Integer, primary_key=True)
    title      = db.Column(db.String(200), nullable=False)  # database rejects empty titles
    done       = db.Column(db.Boolean, default=False)        # new todos start as not done
    created_at = db.Column(db.DateTime, default=datetime.utcnow)  # set once when created

    def __repr__(self):
        return f'<Todo {self.id}: {self.title}>'

# app_context() gives Flask-SQLAlchemy the app reference it needs to connect.
# create_all() creates the todos.db file and the todos table on first run;
# on subsequent runs it does nothing (it never drops or overwrites existing tables).
with app.app_context():
    db.create_all()

Routes - List, Create, Toggle, Delete

All four operations (list, create, toggle, delete) live in app.py alongside the model. Each @app.route() decorator registers a URL path and the HTTP methods that path accepts - if you omit the methods argument, Flask only allows GET requests and rejects everything else with a 405 error. After every change we immediately redirect back to the list - this is called the Post/Redirect/Get pattern. Without it, pressing browser refresh after adding a task would re-submit the form and create a duplicate; after the redirect, a refresh only replays a harmless GET request. flash() stores a one-time message in the session so it survives the redirect and is displayed by the base template on the next page, then cleared automatically. get_or_404(todo_id) is shorthand for 'look this record up by its ID, and if nothing is found return a 404 response' - without it you would need to check for None yourself.

python 
# ── Routes ─────────────────────────────────────────────────────────────────

@app.route("/")
def index():
    # Order incomplete tasks first (.asc() on a Boolean puts False before True),
    # then sort within each group by newest first.
    todos = Todo.query.order_by(Todo.done.asc(), Todo.created_at.desc()).all()
    return render_template("index.html", todos=todos)

# methods=["POST"] means this route only accepts POST requests.
# The form in index.html uses method="post" to match.
@app.route("/add", methods=["POST"])
def add():
    title = request.form.get("title", "").strip()  # .strip() removes accidental leading/trailing spaces
    if not title:
        flash("Please enter a task.", "error")   # second arg is the category, used for CSS colour
        return redirect(url_for("index"))
    db.session.add(Todo(title=title))
    db.session.commit()                           # commit() writes the change to the database file
    flash("Task added!", "success")
    return redirect(url_for("index"))             # Post/Redirect/Get - refresh won't re-submit

@app.route("/toggle/<int:todo_id>")
def toggle(todo_id):
    todo = Todo.query.get_or_404(todo_id)  # returns 404 automatically if the id doesn't exist
    todo.done = not todo.done              # 'not' flips True→False and False→True
    db.session.commit()
    return redirect(url_for("index"))

@app.route("/delete/<int:todo_id>")
def delete(todo_id):
    todo = Todo.query.get_or_404(todo_id)
    db.session.delete(todo)
    db.session.commit()
    flash("Task deleted.", "info")
    return redirect(url_for("index"))

if __name__ == "__main__":
    app.run(debug=True)  # debug=True enables auto-reload and detailed error pages during development

Base Template

base.html is the page shell that all other templates inherit from. Instead of copying the nav bar and CSS into every page, you define them once here and child templates only fill in the parts that change. The {% block content %}{% endblock %} pair marks a named slot - when a child template extends this file and defines its own {% block content %}, Flask swaps the child's content into that slot at render time. get_flashed_messages(with_categories=true) retrieves the one-time messages stored by flash() in the previous request - the with_categories=true argument returns both the message text and its category (success, error, info) so you can apply a different CSS colour to each. Flash messages disappear automatically after being displayed once - they will not show up on the next page load.

html 
<!DOCTYPE html>
<class="hl-tag">html lang="en">
<class="hl-tag">head>
  <class="hl-tag">meta charset="UTF-8">
  <class="hl-tag">meta name="viewport" content="width=device-width, initial-scale=1">
  <class="hl-tag">title>{% block title %}Flask Todo{% endblock %}</class="hl-tag">title>
  <class="hl-tag">style>
    * { box-sizing: border-box; margin: 0; padding: 0; }
    body { font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
           background: #f5f7fa; color: #1a1a1a; }
    nav { background: #1a1a1a; color: white; padding: 14px 24px;
          font-size: 1.1rem; font-weight: 600; }
    .container { max-width: 600px; margin: 40px auto; padding: 0 20px; }
    .flash { padding: 10px 16px; border-radius: 6px; margin-bottom: 16px; font-size: .9rem; }
    .flash.success { background: #d4edda; color: #155724; }
    .flash.error   { background: #f8d7da; color: #721c24; }
    .flash.info    { background: #d1ecf1; color: #0c5460; }
  </class="hl-tag">style>
  {% block extra_styles %}{% endblock %}
</class="hl-tag">head>
<class="hl-tag">body>
  <class="hl-tag">nav>Flask Todo</class="hl-tag">nav>
  <class="hl-tag">div class="container">
    {% with messages = get_flashed_messages(with_categories=true) %}
      {% for category, message in messages %}
        <class="hl-tag">div class="flash {{ category }}">{{ message }}</class="hl-tag">div>
      {% endfor %}
    {% endwith %}
    {% block content %}{% endblock %}
  </class="hl-tag">div>
</class="hl-tag">body>
</class="hl-tag">html>

Todo List Template

index.html extends base.html and fills in only the content block - the nav bar, flash messages, and shared CSS are all inherited automatically. {% extends %} means 'this page is a version of the base template'; it is different from {% include %}, which pastes a reusable snippet into the current page. {{ url_for('add') }} generates the correct URL for the add view function - this is safer than hardcoding /add because if you ever rename the route, every link using url_for updates automatically. The toggle action uses a plain <a href> link (a GET request) rather than a form, because toggling a single task is a lightweight, low-risk action. If the action were more sensitive - like submitting a payment - you would use a POST form instead. The done CSS class on the <li> element triggers the text-decoration: line-through rule in the stylesheet, keeping the visual logic in CSS where it belongs.

html 
{% extends "base.html" %}

{% block extra_styles %}
<class="hl-tag">style>

                     border: none; border-radius: 6px; cursor: pointer; font-size: 1rem; }

  .todo-item { display: flex; align-items: center; gap: 12px; padding: 12px 16px;
               background: white; border-radius: 8px; margin-bottom: 8px;
               box-shadow: 0 1px 3px rgba(0,0,0,.08); }
  .todo-item.done .title { text-decoration: line-through; color: #888; }

</class="hl-tag">style>
{% endblock %}

{% block content %}
<class="hl-tag">h2 style="margin-bottom: 20px;">My Tasks</class="hl-tag">h2>

{# Add new task form - submits via POST to /add #}
<class="hl-tag">form class="add-form" action="{{ url_for('add') }}" method="post">
  <class="hl-tag">input type="text" name="title" placeholder="What needs doing?" required autofocus>
  <class="hl-tag">button type="submit">Add</class="hl-tag">button>
</class="hl-tag">form>

{% if todos %}
  <class="hl-tag">ul class="todo-list">
    {% for todo in todos %}
      <class="hl-tag">li class="todo-item {% if todo.done %}done{% endif %}">
        <class="hl-tag">span class="title">{{ todo.title }}</class="hl-tag">span>
        <class="hl-tag">span class="date">{{ todo.created_at.strftime('%b %d') }}</class="hl-tag">span>
        {# Toggle flips the done state - no JS needed, just a GET request #}
        <class="hl-tag">a href="{{ url_for('toggle', todo_id=todo.id) }}" class="btn toggle">
          {% if todo.done %}Undo{% else %}Done{% endif %}
        </class="hl-tag">a>
        <class="hl-tag">a href="{{ url_for('delete', todo_id=todo.id) }}" class="btn delete">Delete</class="hl-tag">a>
      </class="hl-tag">li>
    {% endfor %}
  </class="hl-tag">ul>
{% else %}
  <class="hl-tag">p class="empty">No tasks yet - add one above.</class="hl-tag">p>
{% endif %}
{% endblock %}
