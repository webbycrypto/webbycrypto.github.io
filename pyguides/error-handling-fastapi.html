Error Handling & Resilience

Requires completing CRUD + HTML and Pydantic Models first. Build reliable APIs that fail gracefully with custom exceptions, structured error responses, retries, and circuit breakers.

1

HTTP Exceptions

FastAPI provides HTTPException for standard HTTP errors. Raise it with a status code (400, 404, 500) and detail message. The framework converts it to a JSON error response automatically.

python 
from fastapi import FastAPI, HTTPException

app = FastAPI()

@app.get("/users/{user_id}")
def get_user(user_id: int):
    if user_id < 1:
        raise HTTPException(status_code=400, detail="Invalid user ID")
    if user_id > 1000:
        raise HTTPException(status_code=404, detail="User not found")
    return {"id": user_id}

Custom Exception Classes

Create custom exception classes for domain-specific errors. This makes code more readable and allows centralized error handling logic.

python 
class UserNotFoundError(Exception):
    def __init__(self, user_id: int):
        self.user_id = user_id
        self.message = f"User {user_id} not found"

@app.get("/users/{user_id}")
def get_user(user_id: int):
    user = db.query(User).get(user_id)
    if not user:
        raise UserNotFoundError(user_id)
    return user
3

Exception Handlers

Use @app.exception_handler to convert custom exceptions into HTTP responses. This centralizes error formatting across your API.

python 
@app.exception_handler(UserNotFoundError)
async def user_not_found_handler(request, exc):
    return JSONResponse(
        status_code=404,
        content={"error": exc.message, "user_id": exc.user_id}
    )

// Now UserNotFoundError automatically returns 404 JSON

Structured Error Responses

Return errors in a consistent format. Include error code, message, and details so clients can handle errors programmatically.

json 
{
  "error": {
    "code": "USER_NOT_FOUND",
    "message": "User 123 not found",
    "status": 404,
    "details": {
      "user_id": 123
    },
    "timestamp": "2024-01-01T12:00:00Z"
  }
}

Error Logging

Log errors for debugging. Use Python's logging module to record what happened, when, and with what context. Never log sensitive data like passwords or tokens.

python 
import logging

logger = logging.getLogger(__name__)

@app.get("/data")
def get_data():
    try:
        result = fetch_from_db()
        return result
    except DatabaseError as e:
        logger.error(f"Database error: {e}", exc_info=True)
        raise HTTPException(status_code=500, detail="Server error")

Retry Strategies

Some operations fail temporarily (network timeout, server busy). Retry with exponential backoff: wait 1s, then 2s, then 4s. Use the tenacity library to implement this.

python 
from tenacity import retry, stop_after_attempt, wait_exponential

@retry(
    stop=stop_after_attempt(3),  // max 3 attempts
    wait=wait_exponential(multiplier=1, min=1, max=10)  // exponential backoff
)
def fetch_external_api():
    response = httpx.get("https://api.example.com/data")
    return response.json()

// If first call fails, waits 1s then retries
// If second fails, waits 2s then retries
// If third fails, raises exception
7

Circuit Breaker Pattern

If a service is repeatedly failing, stop trying for a while (circuit breaker is "open"). This prevents wasting time and resources, and lets the service recover.

States: CLOSED (working normally) → OPEN (too many failures, stop trying) → HALF_OPEN (try once, decide whether to close or open again)

Timeout Handling

Operations should have timeouts. If a request takes too long, assume it failed and return an error rather than waiting forever.

python 
@app.get("/fast-data")
def get_data():
    try:
        // 5-second timeout for external API
        response = httpx.get("https://slow-api.example.com", timeout=5.0)
        return response.json()
    except httpx.TimeoutException:
        logger.warning("API timeout")
        raise HTTPException(status_code=504, detail="Service timeout")

Graceful Degradation

When a non-critical service fails, don't fail the whole request. Return partial data or use a fallback. For example, if analytics fail, still return the main content.

python 
@app.get("/post/{post_id}")
def get_post(post_id: int):
    // Main data (required)
    post = db.query(Post).get(post_id)
    if not post:
        raise HTTPException(status_code=404)

    // Related data (optional)
    try:
        comments = db.query(Comment).filter(Comment.post_id == post_id).all()
    except DatabaseError:
        logger.warning("Failed to fetch comments")
        comments = []  // fallback to empty list

    return {"post": post, "comments": comments}

Testing Error Scenarios

Test that errors are handled correctly. Use pytest to mock failures and verify the response format, status code, and logging behavior.

python 
def test_user_not_found(client):
    response = client.get("/users/9999")
    assert response.status_code == 404
    assert response.json()["error"]["code"] == "USER_NOT_FOUND"

def test_retry_on_failure(mocker):
    mock_api = mocker.patch("httpx.get")
    mock_api.side_effect = [TimeoutError(), TimeoutError(), {"data": "success"}]

    result = fetch_with_retry()
    assert result == {"data": "success"}
    assert mock_api.call_count == 3  // retried twice
