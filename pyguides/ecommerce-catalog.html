E-commerce Product Catalog

Build a real product catalog with categories, inventory tracking, query filtering, and paginated listings. Uses FastAPI, SQLAlchemy, SQLite, and Jinja2 templates.

1

What We're Building

This project is a product catalog — the backend of a small online store. It stores products in a SQLite database, lets visitors filter by category and price, and shows paginated results in a Jinja2 template. Every page route returns HTML, not JSON.

text
GET /                          → redirect to /products
GET /products                  → product list with filters + pagination
GET /products/{id}             → single product detail
PATCH /products/{id}/stock     → update stock count (returns JSON)
GET /admin/add                 → add product form
POST /admin/add                → save new product, redirect to list
text
Table: categories
  id        INTEGER  PRIMARY KEY
  name      TEXT     UNIQUE NOT NULL

Table: products
  id            INTEGER  PRIMARY KEY
  name          TEXT     NOT NULL
  description   TEXT
  price         REAL     NOT NULL
  stock_qty     INTEGER  DEFAULT 0    → 0 means out of stock
  is_active     BOOLEAN  DEFAULT TRUE → FALSE hides from catalog
  category_id   INTEGER  FOREIGN KEY REFERENCES categories(id)

Models and Database

SQLAlchemy maps Python classes to database tables. The relationship between Product and Category uses a foreign key — one category can have many products. The back_populates argument lets you navigate from a product to its category and vice versa.

python
from sqlalchemy import Column, Integer, String, Float, Boolean, ForeignKey, Text
from sqlalchemy.orm import relationship
from database import Base


class Category(Base):
    __tablename__ = "categories"

    id   = Column(Integer, primary_key=True, index=True)
    name = Column(String(100), unique=True, nullable=False)

    # back-reference → lets category.products return all products in it
    products = relationship("Product", back_populates="category")


class Product(Base):
    __tablename__ = "products"

    id          = Column(Integer, primary_key=True, index=True)
    name        = Column(String(200), nullable=False)
    description = Column(Text, default="")
    price       = Column(Float, nullable=False)
    stock_qty   = Column(Integer, default=0)     # 0 = out of stock
    is_active   = Column(Boolean, default=True)   # False = hidden from catalog
    category_id = Column(Integer, ForeignKey("categories.id"))

    # forward reference → lets product.category return the Category row
    category = relationship("Category", back_populates="products")
python
from sqlalchemy import create_engine
from sqlalchemy.orm import declarative_base, sessionmaker

DATABASE_URL = "sqlite:///./catalog.db"

# check_same_thread=False required for SQLite with FastAPI
engine = create_engine(
    DATABASE_URL, connect_args={"check_same_thread": False}
)

SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)
Base = declarative_base()


def get_db():
    # yields a DB session, always closes it when the request finishes
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()


def init_db():
    # creates all tables defined on Base; safe to call every startup
    import models  # noqa: F401 — ensures models are registered on Base
    Base.metadata.create_all(bind=engine)

Seed data fills the database with realistic test records so you can see the app working right away. The startup event runs once when the server starts. Checking whether data already exists prevents inserting duplicates on every restart.

from fastapi import FastAPI

from models import Category, Product

List + Filter Endpoint

Query parameters in the URL control which products are returned. All filters are optional — if the user does not provide one, it is simply skipped. SQLAlchemy lets you chain .filter() calls so each parameter either adds a condition or does nothing.

python
from typing import Optional
from fastapi import Depends, Request
from fastapi.responses import HTMLResponse
from fastapi.templating import Jinja2Templates
from sqlalchemy.orm import Session
from database import get_db
from models import Product, Category

templates = Jinja2Templates(directory="templates")


@app.get("/products", response_class=HTMLResponse)
def list_products(
    request: Request,
    category:  Optional[str]   = None,    # filter by category name
    min_price: Optional[float] = None,    # minimum price inclusive
    max_price: Optional[float] = None,    # maximum price inclusive
    in_stock:  Optional[bool]  = None,    # True → only show stock_qty > 0
    page:      int             = 1,       # current page number (1-based)
    page_size: int             = 9,       # rows per page
    db: Session = Depends(get_db),
):
    # start with all active products
    query = db.query(Product).filter(Product.is_active == True)

    if category:
        # join Category table to filter by name
        query = query.join(Category).filter(Category.name == category)

    if min_price is not None:
        # add AND price >= min_price condition
        query = query.filter(Product.price >= min_price)

    if max_price is not None:
        # add AND price <= max_price condition
        query = query.filter(Product.price <= max_price)

    if in_stock:
        # add AND stock_qty > 0 condition
        query = query.filter(Product.stock_qty > 0)

    # → see Step 5 for pagination
text
URL: /products?category=Electronics&min_price=50&in_stock=true

Each filter adds an AND condition to the SQL query:

  WHERE is_active = True
  AND   category.name = 'Electronics'
  AND   price >= 50
  AND   stock_qty > 0

If you omit a query param, that condition is simply not added.
For example /products returns all active products with no extra filtering.

SQLAlchemy builds the SQL lazily — nothing runs until you call
.count() or .all(). Each .filter() call just appends to the WHERE clause.

Pagination

Pagination splits results into pages. You calculate how many rows to skip based on the current page number, fetch only that slice, and pass the total page count to the template so it can render numbered navigation links.

python
    # total number of rows matching all active filters
    total = query.count()

    # ceiling division: e.g. 10 rows / 3 per page = 4 pages (not 3.33)
    total_pages = (total + page_size - 1) // page_size

    # rows to skip: page 1 skips 0, page 2 skips 9, page 3 skips 18, etc.
    offset = (page - 1) * page_size

    # fetch only the rows for the current page
    products = query.offset(offset).limit(page_size).all()

    # all categories for the filter dropdown
    categories = db.query(Category).all()

    return templates.TemplateResponse("products.html", {
        "request":          request,
        "products":         products,
        "categories":       categories,
        "page":             page,
        "total_pages":      total_pages,
        "total":            total,
        "current_category": category,    # preserves active filter in template
        "current_min_price": min_price,
        "current_max_price": max_price,
        "current_in_stock":  in_stock,
    })
html
<div style="display:flex;gap:12px;align-items:center;margin-top:16px;">

  {% if page > 1 %}
    <a href="/products?page={{ page - 1 }}
      {%- if current_category %}&amp;category={{ current_category }}{% endif %}
      {%- if current_min_price %}&amp;min_price={{ current_min_price }}{% endif %}
      {%- if current_max_price %}&amp;max_price={{ current_max_price }}{% endif %}
      {%- if current_in_stock %}&amp;in_stock=true{% endif %}">
      &larr; Previous
    </a>
  {% endif %}

  <span>Page {{ page }} of {{ total_pages }}</span>

  {% if page < total_pages %}
    <a href="/products?page={{ page + 1 }}
      {%- if current_category %}&amp;category={{ current_category }}{% endif %}
      {%- if current_min_price %}&amp;min_price={{ current_min_price }}{% endif %}
      {%- if current_max_price %}&amp;max_price={{ current_max_price }}{% endif %}
      {%- if current_in_stock %}&amp;in_stock=true{% endif %}">
      Next &rarr;
    </a>
  {% endif %}

</div>

<!-- Note: &amp; is used instead of & inside href attributes so the
     HTML is valid. Browsers convert &amp; back to & when building the URL. -->

Product Detail Page

The detail page shows a single product by its ID. If the ID does not exist in the database, you raise an HTTPException with a 404 status code. You can also query related products from the same category so visitors have something to browse next.

python
from fastapi import HTTPException


@app.get("/products/{product_id}", response_class=HTMLResponse)
def product_detail(
    request: Request,
    product_id: int,
    db: Session = Depends(get_db),
):
    # look up the product by primary key
    product = db.query(Product).filter(Product.id == product_id).first()

    if not product:
        # return 404 page if the product does not exist
        raise HTTPException(status_code=404, detail="Product not found")

    # fetch up to 3 other active products in the same category
    related = (
        db.query(Product)
        .filter(
            Product.category_id == product.category_id,
            Product.id != product_id,       # exclude the current product
            Product.is_active == True,
        )
        .limit(3)
        .all()
    )

    return templates.TemplateResponse("product_detail.html", {
        "request": request,
        "product": product,
        "related": related,
    })

Inventory Update

Stock levels change as products are bought or restocked. This endpoint adjusts the stock count by a delta value — pass a positive number to add stock, a negative number to remove it. The route validates that the result cannot go below zero.

python
from pydantic import BaseModel
from fastapi.responses import JSONResponse


class StockUpdate(BaseModel):
    delta: int   # positive → add stock, negative → remove stock


@app.patch("/products/{product_id}/stock")
def update_stock(
    product_id: int,
    update: StockUpdate,
    db: Session = Depends(get_db),
):
    product = db.query(Product).filter(Product.id == product_id).first()

    if not product:
        raise HTTPException(status_code=404, detail="Product not found")

    # calculate the new quantity before applying the change
    new_qty = product.stock_qty + update.delta

    if new_qty < 0:
        # reject if the result would put stock into negative territory
        raise HTTPException(
            status_code=400,
            detail="Stock cannot go below zero",
        )

    product.stock_qty = new_qty
    db.commit()
    db.refresh(product)

    # return JSON so this endpoint can be called from JavaScript or curl
    return {"id": product.id, "stock_qty": product.stock_qty}
bash
# Add 10 units to product ID 1
curl -X PATCH http://localhost:8000/products/1/stock \
  -H "Content-Type: application/json" \
  -d '{"delta": 10}'
# Response: {"id": 1, "stock_qty": 52}

# Remove 3 units from product ID 1
curl -X PATCH http://localhost:8000/products/1/stock \
  -H "Content-Type: application/json" \
  -d '{"delta": -3}'
# Response: {"id": 1, "stock_qty": 49}

# Attempt to remove more than available → returns 400
curl -X PATCH http://localhost:8000/products/1/stock \
  -H "Content-Type: application/json" \
  -d '{"delta": -999}'
# Response: {"detail": "Stock cannot go below zero"}

What's Next

The catalog is fully working at this point. Here are three natural next steps to extend it further.

Adding a cart
A session-based cart stores item IDs and quantities in the user's browser session. Add POST /cart/add writing to request.session["cart"] — a dict of {product_id: quantity}. See the Jinja2 Templates guide for session middleware setup with itsdangerous.
Image uploads
Products need images. The File Uploads guide covers saving images to disk with UUID filenames and serving them back as static files. Add an image_path column to your Product model for the file path.
Full-text search
SQLite has a built-in full-text search extension called FTS5. Create a virtual FTS5 table that mirrors your product names and descriptions, then query it with MATCH for fast keyword search without any external service.
