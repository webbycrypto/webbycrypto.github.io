FastAPI API Interaction Patterns

Requires completing JavaScript Foundations first. Learn real-world API patterns including authentication, file uploads, pagination, polling, and WebSockets.

1

Structuring Request Bodies and Options

POST and PATCH requests send data in the body. The fetch options object controls the method, headers, and body. Always set Content-Type to application/json for JSON data.

javascript 
const createProduct = async (name, price) => {
  const response = await fetch("/api/products", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ name: name, price: price })
  });
  return await response.json();
};
javascript 
const updateProduct = async (id, updates) => {
  const response = await fetch("/api/products/" + id, {
    method: "PATCH",                                  // PATCH for partial updates
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(updates)                        // only changed fields
  });
  return await response.json();
};
2

Query Parameters and Search

Query parameters go after the question mark in the URL. Use them for filtering and searching. Build them with URLSearchParams to avoid encoding mistakes.

javascript 
// Manual URL building
const search = "laptop";
const limit = 10;
const url = "/api/products?search=" + search + "&limit=" + limit;
const products = await fetch(url).then(r => r.json());
javascript 
// URLSearchParams handles encoding automatically
const params = new URLSearchParams({
  search: "laptop",
  limit: 10,
  sort: "price_asc"
});
const url = "/api/products?" + params;
const products = await fetch(url).then(r => r.json());
3

Handling Validation Error Responses

FastAPI returns 422 Unprocessable Entity when data validation fails. The response includes a detail array explaining which fields failed and why.

javascript 
try {
  const response = await fetch("/api/products", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ name: "", price: "invalid" })
  });

  if (response.status === 422) {  // validation error
    const error = await response.json();
    console.log(error.detail);  // array of field errors
  } else if (response.ok) {
    const product = await response.json();
    console.log(product);
  }
} catch (err) {
  console.error("Network error", err);
}
4

State Management in the UI

Keep track of request state with variables. Show loading spinners while fetching, display errors if the request fails, and show the data when it arrives.

html 
<div id="status"></div>          // shows loading/error/success
<div id="products"></div>        // shows the product list
javascript 
const loadProducts = async () => {
  const statusDiv = document.getElementById("status");
  const productsDiv = document.getElementById("products");

  statusDiv.textContent = "Loading...";

  try {
    const response = await fetch("/api/products");
    if (!response.ok) throw new Error("Request failed");

    const products = await response.json();

    statusDiv.textContent = "Success";
    productsDiv.textContent = JSON.stringify(products);
  } catch (err) {
    statusDiv.textContent = "Error: " + err.message;
  }
};

loadProducts();
5

JWT Login Flow

JWT authentication starts with login. The backend returns an access token. Store it in localStorage and send it with every request. Tokens expire, so handle 401 Unauthorized by asking the user to log in again.

javascript 
const login = async (email, password) => {
  const response = await fetch("/api/auth/login", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ email: email, password: password })
  });

  if (!response.ok) throw new Error("Login failed");

  const data = await response.json();
  localStorage.setItem("token", data.access_token);  // store the token
  return data;
};
6

Authorization Headers and Bearer Tokens

Once logged in, retrieve the token from localStorage and send it with every request in the Authorization header using Bearer format.

javascript 
const getProtectedData = async () => {
  const token = localStorage.getItem("token");

  const response = await fetch("/api/profile", {
    headers: { "Authorization": "Bearer " + token }
  });

  if (response.status === 401) {  // token expired
    localStorage.removeItem("token");
    throw new Error("Please log in again");
  }

  return await response.json();
};
7

File Uploads with FormData

FormData is a browser API for multipart form submission. It handles files and text fields together without needing to manually encode them.

html 
<form id="uploadForm">
  <input type="text" id="productName" placeholder="Product name" />
  <input type="file" id="productImage" accept="image/*" />
  <button type="submit">Upload</button>
</form>
javascript 
const form = document.getElementById("uploadForm");

form.addEventListener("submit", async (e) => {
  e.preventDefault();

  const formData = new FormData();
  // Add text fields
  formData.append("name", document.getElementById("productName").value);
  // Add file input
  formData.append("image", document.getElementById("productImage").files[0]);

  const response = await fetch("/api/products", {
    method: "POST",
    // do NOT set Content-Type, browser does it
    body: formData
  });

  const product = await response.json();
  console.log(product);
});
8

Working with API Pagination

Large datasets are split into pages. The API returns a limit, skip, and total. Use these to implement next/previous buttons and calculate total pages.

javascript 
let currentPage = 1;
const pageSize = 10;

const loadProducts = async (page) => {
  const skip = (page - 1) * pageSize;
  const params = new URLSearchParams({ skip: skip, limit: pageSize });

  const response = await fetch("/api/products?" + params);
  const data = await response.json();

  // data.items contains the products
  // data.total is the total count of all products
  const totalPages = Math.ceil(data.total / pageSize);

  console.log("Page " + page + " of " + totalPages);
  currentPage = page;
  return data.items;
};
9

Request Cancellation and Timeouts

Long-running requests can be cancelled with AbortController. This is useful when the user navigates away or wants to stop a request.

javascript 
const controller = new AbortController();

// Start the request
const response = await fetch("/api/products", {
  signal: controller.signal  // give the controller to fetch
});

// Later, user clicks "Cancel"
controller.abort();  // cancels the fetch request
javascript 
const fetchWithTimeout = (async (url, timeout = 5000) => {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), timeout);

  try {
    return await fetch(url, { signal: controller.signal });
  } finally {
    clearTimeout(timer);
  }
});
10

Polling for Updates

Polling means fetching repeatedly at intervals. Set an interval to check for new data every few seconds. Clear the interval when you're done or the user leaves.

javascript 
let pollInterval;

const startPolling = () => {
  // Check for updates every 3 seconds
  pollInterval = setInterval(async () => {
    const response = await fetch("/api/orders");
    const orders = await response.json();
    // Update the page with new orders
    console.log(orders);
  }, 3000);  // 3000 ms = 3 seconds
};

const stopPolling = () => {
  clearInterval(pollInterval);  // stop checking
};

startPolling();
11

Basic WebSocket Connections

WebSockets maintain an open connection instead of closing after each request. Use them for real-time updates that don't need a full HTTP roundtrip.

javascript 
const ws = new WebSocket("ws://localhost:8001/ws/notifications");

// Connection opened
ws.onopen = () => {
  console.log("Connected to WebSocket");
};

// Server sends a message
ws.onmessage = (event) => {
  const data = JSON.parse(event.data);
  console.log("Got message:", data);
};

// Connection closed
ws.onclose = () => {
  console.log("Disconnected from WebSocket");
};
12

Handling Real-Time Events

Update the page when WebSocket messages arrive. Parse the message, update the DOM, and show the user the new data immediately.

javascript 
const ws = new WebSocket("ws://localhost:8001/ws/orders");
const ordersList = document.getElementById("orders");

ws.onmessage = (event) => {
  const newOrder = JSON.parse(event.data);

  // Create a new list item for the order
  const li = document.createElement("li");
  li.textContent = "Order #" + newOrder.id + ": " + newOrder.status;
  ordersList.appendChild(li);

  // Scroll to the new order so user sees it
  li.scrollIntoView({ behavior: "smooth" });
};
