CORS Fundamentals

CORS (Cross-Origin Resource Sharing) controls which websites can make requests to your API. A browser blocks requests from a different origin unless the server explicitly allows it. Origins are different when domain, protocol, or port differ.

text 
Same origin (no CORS needed):
https://example.com/page1
https://example.com/page2  ← same domain, protocol, port

Different origins (CORS needed):
https://example.com        ← port 443
https://example.com:8000   ← port 8000 (different!)

https://example.com        ← HTTPS
http://example.com         ← HTTP (different protocol!)

https://example.com        ← example.com
https://app.example.com    ← different subdomain (different!)
text 
Browser makes request from https://app.example.com to https://api.example.com

1. Browser checks: are these the same origin?
   - Different subdomains → NO

2. Browser blocks the request and waits for CORS headers

3. Server must send:
   Access-Control-Allow-Origin: https://app.example.com
   (or *)

4. If header is present, browser allows the request
   If missing, request fails (CORS error)

CORS in FastAPI

Use CORSMiddleware to allow cross-origin requests. Specify which origins, methods, and headers are allowed. For public APIs, allow all origins with allow_origins=["*"]. For SaaS, whitelist specific domains.

python 
from fastapi.middleware.cors import CORSMiddleware
from fastapi import FastAPI

app = FastAPI()

// Allow all origins (for public APIs)
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],             // any domain can request
    allow_credentials=False,         // don't send cookies
    allow_methods=["*"],            // GET, POST, DELETE, etc.
    allow_headers=["*"]             // any header
)

@app.get("/api/public")
def public_endpoint():
    return {"data": "public"}
python 
from fastapi.middleware.cors import CORSMiddleware

// Allow only specific domains
allowed_origins = [
    "https://app.example.com",
    "https://admin.example.com"
]

app.add_middleware(
    CORSMiddleware,
    allow_origins=allowed_origins,     // only these domains
    allow_credentials=True,          // allow cookies/auth
    allow_methods=["GET", "POST", "PATCH"],  // specific methods
    allow_headers=["Authorization", "Content-Type"]
)

CSRF Attacks

CSRF (Cross-Site Request Forgery) happens when a hacker tricks a logged-in user into making unwanted requests. A CSRF token ensures requests came from your app, not from another website. FastAPI's CORS protection mostly prevents this, but add CSRF tokens for extra safety with browser-based forms.

Example attack: User is logged into their bank. Hacker's website has a hidden form that transfers money. Since the user is already logged in, the request succeeds. A CSRF token would stop this because the token is specific to your domain.

SQL Injection Prevention

Never concatenate user input into SQL queries. Always use parameterized queries where placeholders (?) are filled safely by the database driver. SQLAlchemy does this automatically when you use the ORM.

python 
// NEVER do this!
search_term = request.query_params.get("q")
query = f"SELECT * FROM users WHERE name = '{search_term}'"
// If search_term = "'; DROP TABLE users; --"
// Database executes: DROP TABLE users!
python 
// Use SQLAlchemy ORM (safe)
@app.get("/search")
def search(q: str, db: Session = Depends(get_db)):
    users = db.query(User).filter(User.name.like(f"%{q}%")).all()
    return users
    // SQLAlchemy escapes q automatically

Rate Limiting

Rate limiting stops attackers from brute-forcing passwords or DDoS attacks by allowing only N requests per time window (e.g., 5 requests per minute). Use SlowAPI to enforce this in FastAPI.

python 
from slowapi import Limiter
from slowapi.util import get_remote_address

limiter = Limiter(key_func=get_remote_address)
app.state.limiter = limiter

// Allow 5 logins per hour per IP
@app.post("/login")
@limiter.limit("5/hour")
def login(request: Request, credentials: LoginRequest):
    return authenticate(credentials)

// Allow 100 requests per minute to public endpoint
@app.get("/api/data")
@limiter.limit("100/minute")
def get_data(request: Request):
    return {"data": []}

Input Validation

Always validate and constrain user input using Pydantic. Set min/max lengths, regex patterns, and enum values. Reject anything that doesn't match the expected format.

python 
from pydantic import BaseModel, Field, validator

class User(BaseModel):
    username: str = Field(min_length=3, max_length=20)
    email: str = Field(regex=r"^[\\w\\.-]+@[\\w\\.-]+\\.\\w+$")
    age: int = Field(ge=0, le=150)  // greater than 0, less than 150

    @validator('username')
    def validate_username(cls, v):
        if "admin" in v.lower():
            raise ValueError("Username cannot contain 'admin'")
        return v

@app.post("/register")
def register(user: User):
    // If request violates any Field constraint, FastAPI returns 422
    return {"status": "registered"}

API Key Security

API keys should be stored securely, rotated regularly, and never exposed in client-side code. Use environment variables, rate limit by key, and log when keys are used. Revoke compromised keys immediately.

python 
import os
from fastapi.security import APIKeyHeader

api_key_header = APIKeyHeader(name="X-API-Key")

def verify_api_key(api_key: str = Depends(api_key_header)):
    valid_key = os.getenv("API_KEY")
    if api_key != valid_key:
        raise HTTPException(status_code=403, detail="Invalid API key")
    return api_key

@app.get("/api/data")
def get_data(api_key: str = Depends(verify_api_key)):
    return {"data": "only for key holders"}

Response Headers Security

Security headers tell browsers and proxies how to handle your content. Add headers to prevent clickjacking, disable caching of sensitive data, enforce HTTPS, and prevent MIME sniffing.

python 
from fastapi.middleware import Middleware
from starlette.middleware.base import BaseHTTPMiddleware

class SecurityHeadersMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        response = await call_next(request)
        response.headers["X-Content-Type-Options"] = "nosniff"  // prevent MIME sniffing
        response.headers["X-Frame-Options"] = "DENY"            // prevent clickjacking
        response.headers["X-XSS-Protection"] = "1; mode=block"   // XSS protection
        response.headers["Strict-Transport-Security"] = "max-age=31536000; includeSubDomains"
        return response

app.add_middleware(SecurityHeadersMiddleware)

HTTPS Enforcement

Always use HTTPS in production to encrypt data in transit. Redirect HTTP to HTTPS, set secure cookies, and use HSTS headers to tell browsers to always use HTTPS.

python 
from fastapi.middleware.trustedhost import TrustedHostMiddleware

// Only accept requests from your domain
app.add_middleware(
    TrustedHostMiddleware,
    allowed_hosts=["example.com", "*.example.com"]
)

// Redirect HTTP to HTTPS
from fastapi.middleware.httpsredirect import HTTPSRedirectMiddleware
app.add_middleware(HTTPSRedirectMiddleware)

// In production, use: uvicorn app:app --ssl-keyfile key.pem --ssl-certfile cert.pem

Security Checklist

Before deploying to production, verify you've covered all critical security areas. This checklist helps ensure no common vulnerabilities slip through.

Pre-deployment checklist:
✅ HTTPS enabled (SSL certificate installed)
✅ CORS configured (whitelist allowed origins)
✅ Rate limiting enabled (SlowAPI on auth endpoints)
✅ Input validation (Pydantic constraints)
✅ SQL injection prevented (using ORM, not f-strings)
✅ API keys not hardcoded (using env vars)
✅ Security headers set (X-Frame-Options, etc.)
✅ HSTS enabled (force HTTPS)
✅ Secrets rotated (JWT keys, API keys, DB password)
✅ Logging enabled (audit trail for security events)
✅ Error responses don't leak info (generic messages to users)
✅ Dependencies updated (no known vulnerabilities)
