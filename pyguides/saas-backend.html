B2B SaaS Backend

Build the backend of a multi-tenant SaaS product. Covers organization management, role-based access control, subscription plans, feature gating, a Jinja2 dashboard, and an audit log.

1

What We're Building

A B2B SaaS app serves companies, not individual users. Each company is an "Organization." Users belong to an organization and have a role that controls what they can do. The organization pays for a subscription plan that determines which features are available to everyone in it.

text
Organization
  └── Users (each with a role: owner / admin / member)
  └── Subscription (plan: starter / pro / enterprise)

Roles control who can do what (RBAC)
Subscription plan controls which features exist (feature gating)

Request flow:
  HTTP request
    → authenticate user (get user from session/token)
    → check role (require_role dependency)
    → check plan feature (check_feature dependency)
    → run route handler
    → log audit event
    → return response
text
POST   /orgs                                        create a new organization
GET    /orgs/{org_id}                               get org details
GET    /orgs/{org_id}/members                       list members
POST   /orgs/{org_id}/invite                        add a user to the org
DELETE /orgs/{org_id}/members/{user_id}             remove a member (admin only)
PATCH  /orgs/{org_id}/members/{user_id}/role        change role (owner only)
GET    /orgs/{org_id}/dashboard                     Jinja dashboard page
GET    /orgs/{org_id}/billing                       billing page
PATCH  /orgs/{org_id}/plan                          change plan (owner only)
GET    /orgs/{org_id}/audit                         audit log page

Database Models

Four models work together: Organization stores the company. User belongs to an org and has a role. Subscription tracks the org's current plan. AuditEvent records important actions for the audit log.

python
from sqlalchemy import Column, Integer, String, Boolean, DateTime, ForeignKey, Text
from sqlalchemy.orm import relationship
from sqlalchemy.ext.declarative import declarative_base
from datetime import datetime

Base = declarative_base()


class Organization(Base):
    __tablename__ = "organizations"

    id      = Column(Integer, primary_key=True)
    name    = Column(String(200), nullable=False)
    created_at = Column(DateTime, default=datetime.utcnow)

    # relationships
    users        = relationship("User", back_populates="org")
    subscription = relationship("Subscription", back_populates="org", uselist=False)
    audit_events = relationship("AuditEvent", back_populates="org")


class User(Base):
    __tablename__ = "users"

    id       = Column(Integer, primary_key=True)
    org_id   = Column(Integer, ForeignKey("organizations.id"), nullable=False)
    email    = Column(String(200), unique=True, nullable=False)
    password_hash = Column(String(200), nullable=False)
    # role → "owner" | "admin" | "member"
    role     = Column(String(20), nullable=False, default="member")
    created_at = Column(DateTime, default=datetime.utcnow)

    org = relationship("Organization", back_populates="users")


class Subscription(Base):
    __tablename__ = "subscriptions"

    id        = Column(Integer, primary_key=True)
    org_id    = Column(Integer, ForeignKey("organizations.id"), nullable=False)
    # plan → "starter" | "pro" | "enterprise"
    plan      = Column(String(20), nullable=False, default="starter")
    # status → "active" | "cancelled"
    status    = Column(String(20), nullable=False, default="active")
    # max_users → 5 for starter, 0 means unlimited (pro/enterprise)
    max_users = Column(Integer, nullable=False, default=5)
    created_at = Column(DateTime, default=datetime.utcnow)

    org = relationship("Organization", back_populates="subscription")


class AuditEvent(Base):
    __tablename__ = "audit_events"

    id         = Column(Integer, primary_key=True)
    org_id     = Column(Integer, ForeignKey("organizations.id"), nullable=False)
    user_id    = Column(Integer, ForeignKey("users.id"), nullable=True)  # nullable for system events
    action     = Column(String(100), nullable=False)   # e.g. "invite_member"
    detail     = Column(Text, nullable=True)            # human-readable description
    created_at = Column(DateTime, default=datetime.utcnow)

    org  = relationship("Organization", back_populates="audit_events")
    user = relationship("User")

Organization Management

Creating an organization also creates the first user with the owner role. Only members of an organization can see its data. The org_id in every route makes sure you are always operating on the right organization.

python
from fastapi import FastAPI, Depends, HTTPException
from pydantic import BaseModel
from passlib.context import CryptContext
from sqlalchemy.orm import Session

app = FastAPI()
pwd_ctx = CryptContext(schemes=["bcrypt"], deprecated="auto")


class CreateOrgRequest(BaseModel):
    name:           str
    owner_email:    str
    owner_password: str


@app.post("/orgs")
def create_org(body: CreateOrgRequest, db: Session = Depends(get_db)):
    # 1. create the organization
    org = Organization(name=body.name)
    db.add(org)
    db.flush()  # get org.id before committing

    # 2. create the owner user
    owner = User(
        org_id        = org.id,
        email         = body.owner_email,
        password_hash = pwd_ctx.hash(body.owner_password),
        role          = "owner",
    )
    db.add(owner)

    # 3. create a starter subscription for the org
    sub = Subscription(
        org_id    = org.id,
        plan      = "starter",
        status    = "active",
        max_users = 5,   # starter → 5 seats
    )
    db.add(sub)
    db.commit()

    return {"org_id": org.id, "message": "Organization created"}
python
@app.get("/orgs/{org_id}/members")
def list_members(org_id: int, db: Session = Depends(get_db)):
    members = db.query(User).filter(User.org_id == org_id).all()
    return [
        {"id": u.id, "email": u.email, "role": u.role}
        for u in members
    ]


class InviteRequest(BaseModel):
    email:    str
    password: str
    role:     str = "member"  # default new members to "member"


@app.post("/orgs/{org_id}/invite")
def invite_member(
    org_id: int,
    body:   InviteRequest,
    db:     Session = Depends(get_db),
):
    sub = db.query(Subscription).filter(Subscription.org_id == org_id).first()
    if not sub:
        raise HTTPException(status_code=404, detail="Subscription not found")

    # check seat limit — max_users == 0 means unlimited
    if sub.max_users > 0:
        current_count = db.query(User).filter(User.org_id == org_id).count()
        if current_count >= sub.max_users:
            raise HTTPException(
                status_code=403,
                detail=f"Seat limit reached ({sub.max_users} users on {sub.plan} plan)",
            )

    new_user = User(
        org_id        = org_id,
        email         = body.email,
        password_hash = pwd_ctx.hash(body.password),
        role          = body.role,
    )
    db.add(new_user)
    db.commit()
    return {"user_id": new_user.id, "message": "Member invited"}

RBAC Roles

Role-Based Access Control (RBAC) means every action is only allowed for certain roles. Instead of checking roles inside every route, you write a dependency factory called require_role(). You pass it a list of allowed roles and it returns a FastAPI dependency that checks the current user's role automatically.

python
from fastapi import Depends, HTTPException


def require_role(*allowed_roles: str):
    """Returns a dependency that checks the current user's role."""
    def dependency(current_user: User = Depends(get_current_user)):
        if current_user.role not in allowed_roles:
            raise HTTPException(
                status_code=403,
                detail=f"This action requires one of: {', '.join(allowed_roles)}",
            )
        return current_user
    return dependency


# Usage examples:
# owner only:             Depends(require_role("owner"))
# owner or admin:         Depends(require_role("owner", "admin"))
# any member:             Depends(require_role("owner", "admin", "member"))
python
from fastapi import Request, HTTPException
from sqlalchemy.orm import Session

# Simplified version: reads user_id from a session cookie.
# In production, decode a JWT from the Authorization header instead.
# See the JWT guide for the full implementation.

def get_current_user(request: Request, db: Session = Depends(get_db)) -> User:
    user_id = request.session.get("user_id")
    if not user_id:
        raise HTTPException(status_code=401, detail="Not authenticated")

    user = db.query(User).filter(User.id == user_id).first()
    if not user:
        raise HTTPException(status_code=401, detail="User not found")

    return user

Subscription Plans

The subscription is stored in the database and linked to the organization. When the org upgrades or downgrades, you update the subscription record. The plan name controls which features are available.

python
# Single source of truth for what each plan includes.
# Always read from this dict — never hardcode limits in routes.

PLAN_FEATURES = {
    "starter": {
        "max_users":        5,
        "advanced_reports": False,
        "audit_export":    False,
        "sso":             False,
    },
    "pro": {
        "max_users":        0,    # 0 = unlimited
        "advanced_reports": True,
        "audit_export":    False,
        "sso":             False,
    },
    "enterprise": {
        "max_users":        0,
        "advanced_reports": True,
        "audit_export":    True,
        "sso":             True,
    },
}

VALID_PLANS = list(PLAN_FEATURES.keys())  # ["starter", "pro", "enterprise"]
python
class ChangePlanRequest(BaseModel):
    new_plan: str


@app.patch("/orgs/{org_id}/plan")
def change_plan(
    org_id:       int,
    body:         ChangePlanRequest,
    db:           Session = Depends(get_db),
    current_user: User    = Depends(require_role("owner")),
):
    # validate the requested plan name
    if body.new_plan not in VALID_PLANS:
        raise HTTPException(
            status_code=400,
            detail=f"Invalid plan. Choose from: {', '.join(VALID_PLANS)}",
        )

    sub = db.query(Subscription).filter(Subscription.org_id == org_id).first()
    if not sub:
        raise HTTPException(status_code=404, detail="Subscription not found")

    old_plan = sub.plan
    sub.plan      = body.new_plan
    sub.max_users = PLAN_FEATURES[body.new_plan]["max_users"]
    db.commit()

    # log the change in the audit log
    log_event(
        db,
        org_id  = org_id,
        user_id = current_user.id,
        action  = "plan_changed",
        detail  = f"Plan changed from {old_plan} to {body.new_plan}",
    )

    return {"message": f"Plan updated to {body.new_plan}"}

Feature Gating

Feature gating means certain routes or UI sections are only available on certain plans. The check_feature() dependency reads the org's current plan, looks up the feature in PLAN_FEATURES, and raises a 403 with a clear upgrade message if the feature is not included.

python
def check_feature(feature_name: str):
    """Returns a dependency that blocks access if the org's plan lacks the feature."""
    def dependency(org_id: int, db: Session = Depends(get_db)):
        sub = db.query(Subscription).filter(Subscription.org_id == org_id).first()
        if not sub:
            raise HTTPException(status_code=404, detail="Subscription not found")

        features = PLAN_FEATURES.get(sub.plan, {})
        if not features.get(feature_name):
            raise HTTPException(
                status_code=403,
                detail=f"'{feature_name}' is not available on the {sub.plan} plan. Upgrade to access it.",
            )
    return dependency


# Usage: combine with require_role for full protection
@app.get("/orgs/{org_id}/reports/advanced")
async def advanced_reports(
    org_id:       int,
    _:            None = Depends(check_feature("advanced_reports")),
    current_user: User = Depends(require_role("owner", "admin", "member")),
    db:           Session = Depends(get_db),
):
    return {"message": "Advanced report data here"}


@app.get("/orgs/{org_id}/audit/export")
async def export_audit(

    _:            None = Depends(check_feature("audit_export")),
    current_user: User = Depends(require_role("owner", "admin")),
    db:           Session = Depends(get_db),

Jinja Dashboard

The dashboard is the main page an org member sees after logging in. It shows who is in the org, what plan they are on, and how many seats are used. Pass everything the template needs from the route. The template itself should only do display logic.

python
from fastapi import Request
from fastapi.responses import HTMLResponse
from fastapi.templating import Jinja2Templates

templates = Jinja2Templates(directory="templates")


@app.get("/orgs/{org_id}/dashboard", response_class=HTMLResponse)
def dashboard(
    org_id:       int,
    request:      Request,
    db:           Session = Depends(get_db),
    current_user: User    = Depends(require_role("owner", "admin", "member")),
):
    org = db.query(Organization).filter(Organization.id == org_id).first()
    if not org:
        raise HTTPException(status_code=404, detail="Org not found")

    members = db.query(User).filter(User.org_id == org_id).all()
    sub     = db.query(Subscription).filter(Subscription.org_id == org_id).first()
    features = PLAN_FEATURES.get(sub.plan, {})

    # last 5 audit events for the activity feed
    recent_events = (
        db.query(AuditEvent)
        .filter(AuditEvent.org_id == org_id)
        .order_by(AuditEvent.created_at.desc())
        .limit(5)
        .all()
    )

    return templates.TemplateResponse("dashboard.html", {
        "request":       request,
        "org":           org,
        "members":       members,
        "member_count":  len(members),
        "sub":           sub,
        "features":      features,
        "current_user":  current_user,
        "recent_events": recent_events,
    })

Member Management UI

Admins and owners need a page to add and remove members without using the API directly. A simple form with a POST action handles both. After each action, redirect back to the same page with a flash message.

python
from fastapi import Form
from fastapi.responses import RedirectResponse


@app.get("/orgs/{org_id}/members", response_class=HTMLResponse)
def members_page(
    org_id:       int,
    request:      Request,
    db:           Session = Depends(get_db),
    current_user: User    = Depends(require_role("owner", "admin")),
):
    members = db.query(User).filter(User.org_id == org_id).all()
    sub     = db.query(Subscription).filter(Subscription.org_id == org_id).first()
    flash   = request.session.pop("flash", None)
    return templates.TemplateResponse("members.html", {
        "request": request, "org_id": org_id,
        "members": members, "sub": sub, "flash": flash,
        "current_user": current_user,
    })


@app.post("/orgs/{org_id}/invite")
def invite_form(
    org_id:       int,
    request:      Request,
    email:        str = Form(...),
    password:     str = Form(...),
    db:           Session = Depends(get_db),
    current_user: User    = Depends(require_role("owner", "admin")),
):
    sub = db.query(Subscription).filter(Subscription.org_id == org_id).first()

    # check seat limit before adding
    if sub.max_users > 0:
        count = db.query(User).filter(User.org_id == org_id).count()
        if count >= sub.max_users:
            request.session["flash"] = f"Seat limit reached ({sub.max_users} seats on {sub.plan} plan)"
            return RedirectResponse(f"/orgs/{org_id}/members", status_code=303)

    new_user = User(
        org_id        = org_id,
        email         = email,
        password_hash = pwd_ctx.hash(password),
        role          = "member",
    )
    db.add(new_user)
    log_event(db, org_id, current_user.id, "invite_member", f"Invited {email}")
    db.commit()

    request.session["flash"] = f"{email} has been added to the organization"
    return RedirectResponse(f"/orgs/{org_id}/members", status_code=303)
python
@app.post("/orgs/{org_id}/members/{user_id}/remove")
def remove_member(
    org_id:       int,
    user_id:      int,
    request:      Request,
    db:           Session = Depends(get_db),
    current_user: User    = Depends(require_role("owner", "admin")),
):
    target = db.query(User).filter(
        User.id == user_id, User.org_id == org_id
    ).first()
    if not target:
        raise HTTPException(status_code=404, detail="Member not found")
    if target.role == "owner":
        raise HTTPException(status_code=403, detail="Cannot remove the org owner")

    log_event(db, org_id, current_user.id, "remove_member", f"Removed {target.email}")
    db.delete(target)
    db.commit()

    request.session["flash"] = f"{target.email} has been removed"
    return RedirectResponse(f"/orgs/{org_id}/members", status_code=303)


@app.post("/orgs/{org_id}/members/{user_id}/role")
def change_member_role(
    org_id:       int,
    user_id:      int,
    request:      Request,
    new_role:     str = Form(...),
    db:           Session = Depends(get_db),
    current_user: User    = Depends(require_role("owner")),  # owner only
):
    if new_role not in ("owner", "admin", "member"):
        raise HTTPException(status_code=400, detail="Invalid role")

    target = db.query(User).filter(
        User.id == user_id, User.org_id == org_id
    ).first()
    if not target:
        raise HTTPException(status_code=404, detail="Member not found")

    old_role   = target.role
    target.role = new_role
    log_event(db, org_id, current_user.id, "role_changed",
              f"{target.email} role: {old_role} → {new_role}")
    db.commit()

    request.session["flash"] = f"{target.email} is now {new_role}"
    return RedirectResponse(f"/orgs/{org_id}/members", status_code=303)

Audit Log

An audit log records who did what and when, at the org level. This is useful for compliance and debugging. You write to the audit log from your route handlers whenever a significant action happens. The log is append-only. Never update or delete audit events.

python
from datetime import datetime


# log_event: call this from any route handler to write an audit record.
# Never update or delete existing audit events — only insert.
def log_event(
    db:      Session,
    org_id:  int,
    user_id: int,
    action:  str,
    detail:  str = "",
) -> None:
    event = AuditEvent(
        org_id     = org_id,
        user_id    = user_id,
        action     = action,
        detail     = detail,
        created_at = datetime.utcnow(),
    )
    db.add(event)
    db.commit()


# Where to call log_event in your routes:
#
#   invite_member  → log_event(db, org_id, current_user.id, "invite_member", f"Invited {email}")
#   remove_member  → log_event(db, org_id, current_user.id, "remove_member", f"Removed {email}")
#   change_role    → log_event(db, org_id, current_user.id, "role_changed",  f"{email}: {old} → {new}")
#   change_plan    → log_event(db, org_id, current_user.id, "plan_changed",  f"{old} → {new}")
#   delete_org     → log_event(db, org_id, current_user.id, "org_deleted",   org.name)


@app.get("/orgs/{org_id}/audit", response_class=HTMLResponse)
def audit_page(
    org_id:       int,
    request:      Request,
    db:           Session = Depends(get_db),
    current_user: User    = Depends(require_role("owner", "admin")),
):
    # last 100 events, newest first
    events = (
        db.query(AuditEvent)
        .filter(AuditEvent.org_id == org_id)
        .order_by(AuditEvent.created_at.desc())
        .limit(100)
        .all()
    )
    return templates.TemplateResponse("audit.html", {
        "request": request,
        "org_id":  org_id,
        "events":  events,
    })

What's Next

Real billing with Stripe
In production, the plan upgrade button creates a Stripe Checkout Session and redirects the user to Stripe's payment page. After payment, Stripe sends a webhook to your server to confirm the plan change. The Stripe Python SDK handles all of this. You would gate the plan update inside the webhook handler rather than a direct form POST.
JWT authentication
This guide used a simplified session-based auth for clarity. For a production SaaS app you want JWT access tokens and refresh token rotation so the frontend can be a separate app. The payload carries user_id and org_id so you can remove the session middleware entirely. See the JWT and Refresh Token guides for the full implementation.
Per-org API keys
Many B2B apps let organizations generate API keys for programmatic access. Add an OrgAPIKey table with columns org_id, key_hash (bcrypt or SHA-256), label, and created_at. Create a get_current_org_from_api_key dependency that reads the X-API-Key header, hashes it, and looks it up in the table. Apply this dependency to any routes that need machine-to-machine access.
